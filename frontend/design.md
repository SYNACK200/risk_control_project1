# 这个部分在业务里承担什么

让借款人在三分钟内把材料交对，让银行的人在五分钟内把一份流水看完并能签字。

前端不产生任何判断，只做两件事：**把该收的材料收全**、**把后端给的事实摆清楚**。

# 借款人侧要什么

## 他来这里的目的

交材料，然后知道「我的材料有没有被收下、还缺什么」。**不是**来看自己的分析结果。

## 必须做到

| # | 要求 | 为什么 |
| --- | --- | --- |
| B1 | 上传前就告诉他文件对不对（格式、大小），别等传完才说 | 传完再报错是最容易让人放弃的体验 |
| B2 | 说清「为什么退回」，而不是只说「上传失败」 | 十种原因对应十种处理，含糊等于让他猜 |
| B3 | 加密件当场给输入口令的机会，不要让他重新走一遍 | 重走一遍等于丢一次材料 |
| B4 | 缺哪个月、缺哪一页，逐条列出来 | 「材料不完整」这句话没有行动价值 |
| B5 | 补件入口就在提示旁边，不要让他找 | 找不到就等于没给 |
| B6 | 等待时给出阶段，不转圈 | 转圈会让他重复上传，制造重复任务 |

## 绝对不能出现

| # | 禁止 | 为什么 |
| --- | --- | --- |
| X1 | 三态结论、指标数值、命中标签 | 借款人看到判定口径会针对性改材料，形成反向选择 |
| X2 | 评分、风险等级、建议额度 | 一旦出现就等于替他做了银行该做的判断 |
| X3 | 他自己的明文卡号与身份证 | 合规红线 |
| X4 | 内部规则编码、证据坐标 | 这些是给复核人用的，给他等于泄露判定方法 |

## 交完材料之后的措辞

统一口径：**「材料已提交，请等待银行处理」**。不说「审核中」（暗示我们在审），不说「通过」（预示结果）。

# 支持三类材料，提示要写清差别

## 上传页要能收三种

| 类型 | 扩展名 | 上限 | 前置校验 |
| --- | --- | --- | --- |
| 电子流水 | .pdf | 20MB | 非空、后缀正确 |
| 拍照件 | .jpg/.jpeg | 10MB | 短边 ≥ 1000px |
| 截图 | .png | 10MB | 同上，另提示风险 |

## 要让借款人自己判断该传哪种

不要只写「支持 PDF/图片」，要给一句话结论：

| 材料 | 给他的话 |
| --- | --- |
| 电子件 | 推荐。从手机银行导出后直接上传，处理最快、结果最完整 |
| 拍照件 | 可以用。请把整页拍全、避免反光，处理后会经过人工复核，时间更长 |
| 截图 | 不建议。截图难以核验来源，可能无法作为授信依据 |

**截图不拦**：拦了他会去 PS 一份更像的。收下来、出结论、写明限制，比拦在门口更安全。

## 三类在页面上的差别

| 位置 | 电子件 | 影像件 | 截图 |
| --- | --- | --- | --- |
| 上传后提示 | 已收件 | 已收件，需人工复核 | 已收件，但可能无法作为授信依据 |
| 进度页 | 正常阶段 | 多一句「材料为图片，处理时间较长」 | 同上，并提示结果仅供参考 |
| 银行侧复核页 | 无标记 | 顶部标「影像件 · 待人工复核」 | 顶部标「截图件 · 不得作为授信依据」 |
| 报告 | 无限制说明 | 列出核验受限项 | 结论为来源可疑，且列出受限项 |

# 银行侧要什么

## 三种人三种诉求

| 角色 | 来干什么 | 最怕什么 |
| --- | --- | --- |
| 审批人 | 判断这份材料能不能作为依据 | 结论没有出处，自己签了要担责 |
| 模板管理员 | 把长尾版式录进来 | 录完不敢用，不知道生效没 |
| 运营与系统管理员 | 看系统跑得怎么样、谁能进来 | 出了问题不知道找谁、改了什么没有记录 |

## 必须做到

| # | 要求 | 为什么 |
| --- | --- | --- |
| B7 | 每条结论都能点到具体那一笔、那一页 | 不能复核的报告，审批人不敢用 |
| B8 | 四层核验各自的结论分开显示，不要合并成一个「可信度」 | 合并会掩盖「文件层通过但账务层不可算」这种关键差异 |
| B9 | 指标必须带口径说明与版本号 | 同一份材料在不同口径下数字不同，没有版本就无法对账 |
| B10 | 导出必须留痕：谁、何时、导了哪一版 | 报告离开系统后只能靠这条记录追溯 |
| B11 | 按角色隐藏，不是按角色置灰 | 置灰等于告诉他这里有东西 |
| B12 | 失败任务能重跑，缺件任务能补件，都在同一页完成 | 换个页面就找不到上下文 |

## 绝对不能出现

| # | 禁止 | 为什么 |
| --- | --- | --- |
| X5 | 把四层结论算成一个总分或星级 | 我们不做评分，这是产品边界 |
| X6 | 替审批人写意见模板 | 意见是他的责任，我们不代写 |
| X7 | 对模板内容做「是否准确」的判断 | 模板由银行维护，平台只按模板执行 |

# 页面说明（逐页）

每页都要回答四件事：**谁用、来干什么、看到什么、出问题怎么办**。

## 借款人侧

### F1 上传页

| 项 | 内容 |
| --- | --- |
| 谁用 | 借款人，可能第一次接触，金融知识有限 |
| 目的 | 把材料交上来，并知道交得对不对 |
| 进入 | 首页入口，或退回后重新进入 |
| 必须要素 | **流水文件是唯一必填的数据项；授权确认必须勾选（未勾选不能提交）**；拖拽/选择区（选中后在区内显示文件名、大小、本地检查通过，可重新选择或移除）、支持格式与大小说明、三类载体建议、期间（选填，不得晚于本月）、来源凭证（选填）、上传进度、口令输入（加密件时出现） |
| 状态 | 待选、检查中、已选中（区内文件名片）、校验失败（前置）、上传中、上传失败可重试 |
| 离开 | 成功 → 进度页；退回 → 留在本页并说明原因 |
| 异常 | 格式不对、太大、图片太糊、期间选到未来月份：都在本地先拦，不发请求 |

### F2 进度页

| 项 | 内容 |
| --- | --- |
| 谁用 | 借款人 |
| 目的 | 知道到哪一步了、还要不要补材料 |
| 必须要素 | 阶段条、当前状态一句话、已用时、缺什么（逐条）、补件入口 |
| 状态 | 处理中（轮询）、待补件、失败（原因码 + 建议）、完成 |
| 离开 | 完成 → 只显示「已提交，请等待银行处理」，不跳任何结果页 |
| 异常 | 轮询失败不报错，降级为手动刷新按钮 |

### F3 补件（内嵌在进度页）

| 项 | 内容 |
| --- | --- |
| 目的 | 把缺的那几个月/那几页补上 |
| 必须要素 | 缺失清单（月份、页码）、逐项上传、补完提交 |
| 规则 | 未补完也能提交，但要告诉他还缺几项 |

## 银行侧

### B1 登录页

| 项 | 内容 |
| --- | --- |
| 谁用 | 四类银行角色 |
| 目的 | 进来 |
| 必须要素 | 账号、密码、错误次数提示、锁定提示 |
| 状态 | 初始、失败、锁定 |

### B2 任务工作台

| 项 | 内容 |
| --- | --- |
| 谁用 | 审批人、运营管理员、系统管理员 |
| 目的 | 找到要看的件、处理卡住的件 |
| 必须要素 | 列表（任务号、载体、状态、创建时间、失败码）、筛选（状态/载体/时间）、详情入口、重跑、补件、导出 |
| 状态 | 空（给上传或等待提示）、加载、失败重试 |
| 规则 | 失败件显示原因码与一句处置建议；待补件显示缺项 |

### B3 报告复核页

| 项 | 内容 |
| --- | --- |
| 谁用 | 审批人 |
| 目的 | 判断这份材料能不能用，并留下意见 |
| 必须要素 | 载体标记与待复核标记、五态结论、四层各自结论、核验受限说明、指标表（名称/值/口径/版本）、证据列表（点开定位原页）、导出、意见录入与历史意见 |
| 状态 | 无权限（403 页）、生成中、就绪、导出中、已导出 |
| 规则 | 结论必须能点回原页；影像件与截图件顶部必须有不能忽略的标记 |
| 异常 | 原页打不开 → 显示页码与坐标文本，保证仍可核对 |

### B4 模板管理页（含标注）

| 项 | 内容 |
| --- | --- |
| 谁用 | 模板管理员 |
| 目的 | 把长尾版式录进来、标好字段、启用 |
| 必须要素 | 样例渲染区、框选层、字段选择（内置 + 自建）、表格区与列边界、校验面板、版本列表与启停、样本原件 |
| 状态 | 空、已载入、标注中、有错误、保存成功、启用中、停用 |
| 规则 | 不显示「模板是否准确」的评价——我们不做这个判断；只做结构校验（T/W 码）与试解析对照 |

标注的动作链：载入样例 → 画表格区 → 画列 → 画字段框 → 逐个指定字段 → 看校验清单 → 试解析 → 保存版本。

**校验码**：错误 T001–T010 阻止保存（缺银行、空模板、缺必填字段、表格无列、字段重复、坐标异常、自定义字段非法、列越界、无表头词、框未指定字段）；警告 W001–W005 允许保存（框落在明细区、列重叠、无表格区、无基准尺寸、多页只标首页）。定义见 `algorithm/template-spec.md`。

**试解析**：保存前必须能验一次抽取结果，否则录错了没人知道。接口未接入前，页面明确标注「只做了结构校验」。

### B5 批量筛查页

| 项 | 内容 |
| --- | --- |
| 谁用 | 审批人、运营管理员 |
| 目的 | 看一批数据里哪些命中、逐条复核 |
| 必须要素 | 批次列表（导入时间、进度、命中数）、命中清单（规则编码、笔数、位置）、复核标记 |
| 状态 | 运行中、完成、失败 |
| 规则 | 复核只标记不改原始命中 |

### B6 系统管理页

| 项 | 内容 |
| --- | --- |
| 谁用 | 系统管理员 |
| 目的 | 管人、管规则、查痕迹 |
| 必须要素 | 账号与角色、规则列表与编辑、阈值配置（含版本）、审计查询（按对象与时间） |
| 状态 | 无权限（403）、加载、保存中 |
| 规则 | 阈值修改必须显示「改了会影响哪些结论」并记版本；阈值项与默认值由算法组定义，页面只做展示与提交，不允许前端自己加项 |

# 交互口径（对所有页面生效）

| 场景 | 要怎么做 | 不要怎么做 |
| --- | --- | --- |
| 出错 | 说原因 + 说下一步该干什么 | 只弹「操作失败」 |
| 加载慢 | 给阶段与已用时 | 无限转圈 |
| 没数据 | 说明为什么没有 + 给出入口 | 空白页 |
| 无权限 | 明确告知无权限 | 显示空列表 |
| 长等待 | 允许离开页面，回来还能看到 | 逼用户守着 |

同一件事两种说法：借款人看到的是「怎么办」，银行看到的是「哪里不对」。

# 验收口径（业务判断，不是命令）

| # | 怎么算做对了 |
| --- | --- |
| V1 | 拿十份真实材料找不熟悉这个系统的人试：他能在不提问的情况下把材料交完 |
| V2 | 退回的每一份材料，用户看完提示知道下一步做什么 |
| V3 | 让审批人在不看文档的情况下，从结论点进原页找到那一笔 |
| V4 | 借款人账号无论怎么点，都看不到任何结论与指标 |
| V5 | 每个错误码都有两套文案：借款人听得懂、银行看得懂 |

# 与其他部分的交界

| 交界 | 我方要什么 | 我方给什么 |
| --- | --- | --- |
| 后端 | 每个状态有稳定含义、错误码有明确文案依据、报告含四层与证据 | 按契约提交的参数、真实的上传与补件 |
| 算法 | 不需要直接接触；只消费后端聚合后的结果 | — |
| 数据 | 不需要接触；脱敏在服务端完成 | — |

# 不做

| 不做 | 谁做 |
| --- | --- |
| 判断材料真假 | 算法四层核验 |
| 算指标 | 算法 |
| 脱敏 | 数据与服务端 |
| 生成结论措辞 | 后端报告服务 |
