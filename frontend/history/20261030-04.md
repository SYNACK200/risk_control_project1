# FE-42 上传区文件名片 + 期间禁选未来

## 意图

用户 2026-10-30 提两点：
1. 拖拽/选择文件成功后、提交之前，要能在上传区里看到“这个文件已经选上了”，并显示文件名，而不是只在下方出现一行小字。
2. 选填的期间月份不能选到未来。

## 改动

- `src/pages/UploadPage.tsx`：
  - 拖拽区改为三态：待选（拖拽提示 + 选择文件）、检查中（显示候选文件名）、已选中（绿色 ✓ + “文件已选择” + 文件名 + 大小 + “本地检查通过 · 拖入新文件可替换”，并提供“重新选择”“移除”）。
  - 原来的下方 `.file-row` 移入拖拽区；错误提示仍留在区下方，`aria-live` 播报；文件名片用 `role="status"` 播报文件名。
  - 选新文件会替换旧文件；拖入新文件同样可替换。
  - 期间月份 `input[type=month]` 增加 `max=本月`；同时做 JS 校验，手输未来月份会提示“开始/结束月份不能晚于本月。”并禁用提交，改回本月内自动恢复。
- `src/styles/upload.css`：文件名片样式（紧凑内边距、换行、按钮组）；移除已无用的 `.file-row` 覆盖。
- `design.md`：F1 必须要素、状态、异常补充文件名片与期间上限。
- `tasks.md`：FE-42 记入已完成清单。
- 测试：mock 用例改为真实 `DataTransfer` 拖拽路径，新增文件名在区内、成功状态、月份上限、未来月份报错/禁用/恢复断言；真实后端用例补区内文件名与月份上限。

- `npm run build`：通过（tsc -b + vite build，201ms）。

  - 选择 `gen.pdf` 后区内显示文件名；月份上限为本月。
  - 提交 189ms 进入 `/tasks/7`，后台 DONE，期间 YMD 落库；加密件流程 `/tasks/8` 正常。

## 没做什么

- 未限制“开始月份早于合理下限”（如 1900 年），契约没有下限口径，等 PM/PD。
- 未做拖拽悬停高亮；拖入多文件仍按原逻辑提示“每次一份”。
- 后端未改：期间仍是选填，未来月份的前端拦截不发请求。

## 风险 / 契约偏差（需 PM/PD 确认）

- 契约期间字段只写“选填、取不到则报告注明”，没写不能晚于本月。前端按常识加本地拦截，建议 PM/PD 在期间说明补一句，便于验收对齐。
- 月份上限按浏览器本地时间计算；若用户设备时区异常，最多与本月初相差一天，不影响月份粒度。

## 裁决

- 2026-10-30 用户拍板：上传成功须在区内可见文件名；期间不得选未来月份。
