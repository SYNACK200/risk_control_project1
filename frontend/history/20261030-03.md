# FE-40 授权确认阻断提交

## 意图

上传页原有的“我确认已获授权提交该流水，并同意由银行按授权用途处理。”勾选框只是摆设，不勾也能提交。用户 2026-10-30 拍板：未勾选授权确认不得提交材料。本轮把它做成真正的提交闸门。

## 改动

- `src/pages/UploadPage.tsx`：
  - `canSubmit` 增加 `agreed` 条件；未勾选时提交按钮禁用。
  - 选了文件但未勾选时，按钮上方提示“请勾选授权确认后再提交。”
  - 勾选后提示消失，按原规则（文件、期间校验、口令）决定能否提交。
- `design.md`：F1 必须要素改为“流水文件是唯一必填的数据项；授权确认必须勾选（未勾选不能提交）”。
- `tasks.md`：FE-40 从 P1 移入已完成清单。
- 两套浏览器用例各补授权断言（未勾选禁用 → 勾选可提交 → 取消勾选再次禁用）。

## 验证

- `npm run build`：通过（tsc -b + vite build，277ms）。
- 浏览器（Chrome 1440×900，拦截状态序列）：37/37，其中新增 4 项授权断言全部通过。
- 真实后端（便携 MySQL 8.4.5 + uvicorn，无 mock）：13/13，其中“未勾选授权不能提交”通过；勾选后提交 167ms 跳转 `/tasks/5`，数据库为 DONE、期间 YMD；加密件流程照旧（`/tasks/6`）。
- 未勾选时无任何请求发出，后端受理接口未改。

## 没做什么

- 不改后端：`POST /tasks` 的必填字段仍是只有 `file`，契约 API 未动。
- 未加“已阅读”倒计时、协议弹窗等其他合规交互。

## 风险 / 契约偏差（需 PM/PD 确认）

- `contract.md` 必填清单写的是“唯一必填：流水文件本身。其余一律选填。”——这说的是 API 字段。本轮加的是前端提交前的 UI 闸门，不改变接口，但“未勾选不能提交”实际上让授权确认成为用户侧必填项。建议 PM/PD 在契约必填清单补一句前端授权闸门口径，避免验收时按“其余一律选填”判前端违规。

## 裁决

- 2026-10-30 用户拍板：授权确认必须勾选才能提交（覆盖 v2 基线“勾选与提交解耦”的口径），PR 时交 PM/PD 复核。

## 材料登记

- 本轮未使用真实客户材料，验证用临时目录生成的 `gen.pdf`、`enc.pdf`，未入库、未提交仓库。

## 审查修正（2026-10-30，PM/PD 审查）

原实现把「授权确认」做成提交前置闸门。经核对，2026-10-30 的决策是「唯一必填是流水文件，其余选填」，因此已在合并前改为：授权勾选保留提示、不再禁用提交按钮。若要恢复为必填，需要 PM/PD 明确授权口径后再改。
