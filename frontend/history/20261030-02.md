# FE-08 状态查询 + 前端底座对齐 v2

## 意图

提交后让借款人知道材料到哪一步了：进入进度页、3 秒轮询、完成/失败/待补件可读，轮询失败可手动刷新。同时把上一轮的路由与请求层接到 v2 后端真实响应上（后端返回裸 JSON，不是契约信封）。

## 改动

- `src/App.tsx`、`src/main.tsx`：新增 `/tasks/:taskId` 路由；保留 404；引入进度页样式。
- `src/pages/ProgressPage.tsx`：新增进度页。阶段条（已收件→文件检查→解析流水→核验完成）、状态一句话、已用时、3 秒轮询、DONE/FAILED/NEED_SUPPLEMENT 停止轮询；失败给原因与下一步；待补件给联系指引；查询中/查询失败/无此业务三态；轮询失败降级为手动刷新，恢复后继续轮询。
- `src/pages/UploadPage.tsx`：提交成功跳转进度页；期间月份转 YMD 月首/月末并注明“按整月”；加密件返回 E_ENCRYPT 时出现口令框，未填口令不允许再次提交；提交错误改用双受众文案。
- `src/lib/api.ts`：`createTask` / `getTask` 改走 axios 请求层；`getTask` 返回后端实际字段（`failure_code`、`created_at` 等）。
- `src/api/client.ts`：兼容两种成功响应（契约信封 `{code,message,data}` 与后端裸 JSON），错误从 FastAPI `detail` 或信封中取码；`E_AUTH` 清 token；上传超时放宽到 180 秒。
- `src/api/errors.ts`、`src/lib/auth.ts`、`src/pages/NotFoundPage.tsx`：12 个契约错误码双受众文案、前台只读写 `bs_token`、404 页。
- `src/styles/progress.css`、`package.json`：进度页样式与 axios 依赖。

## 没做什么

- 待补件只有状态与联系指引，没有缺件明细与逐项补传：`GET /tasks/{id}` 无缺件字段，`POST /tasks/{id}/supplement` 未实现。
- FE-19 脱敏自检未做。
- 借款人身份守卫按 2026-10-30 决定暂不做。

## 风险 / 契约偏差（跨部分，需后端或 PM/PD 确认）

- v2 后端成功响应是裸 JSON，错误是 `{detail:{code,message}}`，与契约的 `{code,message,data}` 不一致；前端已兼容两种形态，但长期应统一，否则联调字段各写一套。
- 受理时同步解析，创建即 DONE，真实链路观察不到 PENDING→PARSING；本轮状态流转用拦截序列验证，异步化后需再验一次真实链路。
- `GET /tasks/{id}` 返回 `id` 而非 `task_id`，无 `status_text`、无缺件清单；`created_at` 无时区偏移。
- 解析失败返回契约外的 `E_PARSE`，前端归为通用失败文案。
- 口令尝试未写入审计（契约要求每次尝试留痕）——后端问题，未改后端。
