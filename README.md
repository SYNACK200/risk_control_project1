# 智能风控 · 银行流水分析与真实性核验

> 借款人上传个人流水 → 银行侧拿到 **真实性核验 + 合格性结论 + 40 项指标 + 可追溯报告**。
> 银行内部自建工具：报告只有银行侧可见，借款侧只看到"已收到 / 处理中 / 已完成"。

| 现在是什么 | 值 |
| --- | --- |
| 版本 | `v0.4.0`（规则见 [docs/版本管理规范.md](docs/版本管理规范.md)） |
| 形态 | 单进程：一个后端同时托管 API 和两个前端；分析走 2 进程池 |
| 测试 | 算法 285 通过 · 后端 17 通过 |
| 默认端口 | 8000（`APP_PORT` 可改） |

---

## 1. 五分钟跑起来

前提：Python 3.11+、Node 20+、MySQL 8.x（库表自动创建）。

```bash
cp .env.example .env     # 填 MYSQL_PASSWORD
./scripts/start_unix.sh  # Windows: scripts\start_windows.bat
```

脚本会装依赖 → 构建两个前端 → 起服务。三个入口：

| 入口 | 地址 | 谁用 |
| --- | --- | --- |
| 首页 | http://127.0.0.1:8000/ | 选身份 |
| 借款侧 | http://127.0.0.1:8000/app/ | 借款人：注册、上传、看进度 |
| 银行侧 | http://127.0.0.1:8000/bank/ | 银行：报告、客户与账户、模板、参数 |

银行侧首次启动自动建管理员 `admin`，密码取 `ADMIN_PASSWORD`；留空则随机生成并写入 `backend/.admin_password`。

## 2. 从哪开始用

**借款人**：注册 → 上传 PDF/JPG/PNG（加密件可输口令）→ 只看收件状态。

**银行人员（最短路径）**：

1. 「解析结果」→ 点任务 → 打开**报告**
2. 先看顶部**结论摘要**（一段白话），不需要指标到此为止
3. 要细节：切「明细版」→ 四层逐项 / 40 项指标 / 证据
4. 同一客户多份流水 → 「客户与账户」→ 系统给出**建议合并**对象，可批量合并再逐个看

## 3. 现在能做什么

| 模块 | 能力 |
| --- | --- |
| 受理 | PDF/JPG/PNG、zip 代解、加密件返回 `E_ENCRYPT` 并可输口令 |
| 解析 | 模板解析 + 通用兜底；少量标注外推整表；模板可回看**当时的框选** |
| 真实性 | 四层核验（载体/内容/账务/外部）+ 识别自检 S1–S7；**不可算 ≠ 通过** |
| 结论 | 真实性五态 + 合格性五级（通过 / 可授信 / 需补充 / 不通过 / 无法判定） |
| 指标 | 40 项、5 分区评分（收入/负债/资金/异常/集中度），口径版本化 |
| 报告 | 结论摘要与明细切换、资金全景、导出 CSV/JSON、打印 |
| 账号 | 借款侧注册登录、银行侧登录、角色隔离 |
| 多账户 | 8 种合并口径（用业务问题表述）、系统建议合并 + 手动兜底、多对象对比 |
| 模板 | 标注 → 存草稿 → 启用/停用/复制/试跑/统计/导出导入；被引用时"从列表移除" |
| 风控参数 | 22 项阈值可视化调整、版本化、旧报告不重写 |
| 数据管理 | 回收站（软删除/恢复/彻底删除）、操作审计 |

## 4. 有意不做 / 还没做

| # | 现状 | 影响 |
| --- | --- | --- |
| 1 | 分析已移到**后台进程池**（默认 2 进程），请求立即返回 QUEUED | 请求内仍做第 1 页预读，大量小文件并发时提交仍会被 GIL 串行 |
| 2 | 有排队但队列长度不可见、无失败自动重试 | 高峰期只能看到「排队中」，看不到还有几份在前面 |
| 3 | 影像件像素取证（8 项）未做 | 图片件结论封顶"无法判定" |
| 4 | 印章校验只有方案 | 判断不了"文件是谁出的" |
| 5 | 证据坐标多为空 | 报告能说结论，跳不到原文位置 |
| 6 | 招行方向识别不可靠 | 该版式收入类指标给 `null` |
| 7 | 无限流 / 找回密码 / 银行侧用户管理界面 | 生产前要补 |

```bash

  python -m pytest tests -q                                   # 17

python -m uvicorn main:app --app-dir backend --reload --port 8000
```

## 10. 贡献

```bash
git checkout dev && git pull
git checkout -b feat/模块-任务号
# 改完跑第 6 节测试
git commit -m "feat(模块): 任务号 + 一句话"
git push -u origin feat/模块-任务号   # GitHub 提 PR，目标分支 dev
```

合并顺序固定 `feat/* → dev → main`，合并即删分支，本地只留 `dev` / `main`。
