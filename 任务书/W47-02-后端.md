## 三、任务卡

### BE-101 · 骨架、配置与鉴权（P0，0.5 天）
- `main.py` 起 app；`/healthz` 返回 `{"status":"ok","catalog_version":"1.0","db":"ok"}`
- `auth.py`：`X-Api-Key` 与 `LAB_API_KEY` 常量时间比较；`/healthz`、`/ui/**` 豁免
- 错误信封统一 `{"detail":{"code","message"}}`（**不要**引入 `{code,message,data}`）
- 验收：无 Key → 401 `E_AUTH`；有 Key → 200

### BE-102 · 提交一次计算 + 落库（P0，1.5 天）
- `POST /v1/runs`：校验 rows（≤20000 行 / ≤32MB）、转 `Statement`、调 `compute`
- 幂等：`request_hash = sha256(规范化(profile) + 规范化(rows))`；有效期内命中返回同一 `run_id`
- 落库：写 `lab_run` + `lab_run_value`（表结构见 `任务书/W47-04-数据.md` DA-101）
- 响应含 `available` / `unavailable`（后者带 `reason`）
- 验收：同一份 570 行流水提交两次 → 同一 run_id；**随机打乱 rows 顺序 → 也是同一 run_id**（哈希前要先按内容排序）

### BE-103 · 按 run_id 取指标（P0，1 天）
- `GET /v1/runs/{run_id}/features?codes=`：codes 省略返回全部；未知 code → 404 并列出未知项
- `GET /v1/runs/{run_id}/features/{code}`：单条
- `GET /v1/runs/{run_id}`：概要，不含数值
- 过期 run → `410 E_EXPIRED`（不要 404：业务侧要能区分「没算过」与「过期了」）
- 验收：值一律字符串；`value:null` 必带 `reason`

### BE-104 · 目录与表达式试算（P1，1 天）
- `/v1/catalog/features`：46 条，支持 `category` 与 `q` 过滤
- `/v1/catalog/operators`：83 条（直接复用 `operator_catalog()`）
- `POST /v1/expr/evaluate`：保留 Lab 现在的试算能力（表达式 + rows/sample）
- 自定义特征：**暂迁** `var/lab/custom_features.json` 到 Lab 自己的目录（不迁 DB，降风险），目录接口里与内置特征合并返回
- 验收：目录条数 = 46（业务后端 `/api/v1/lab/features` 现在也是 46，两边必须一致）

### BE-105 · 业务侧客户端（P0，0.5 天）
- `backend/services/lab_client.py`：`httpx` 客户端，三个函数

```python
submit_run(rows, profile=None, codes=None, client_ref=None) -> dict   # 拿 run_id
get_features(run_id, codes=None) -> list[dict]                        # 取指标
get_feature(run_id, code) -> dict                                    # 取单个
```

- 超时 10s、重试 2 次（只重试连接错误与 5xx）、`X-Api-Key` 从 `LAB_API_KEY` 读
- Lab 不可用时**抛 `LabUnavailable`**，业务侧必须有降级路径（报告里标「特征不可用」而不是崩）
- 验收：把 Lab 停掉，业务侧调用得到明确异常且业务主链路不挂

### BE-106 · 兼容代理（P0，0.5 天）
- `backend/routers/lab_bridge.py`：`/api/v1/features/*`、`/api/v1/lab/*` 反代到 8030
- **铁律**：只转发、不改字段、不改状态码；保留 `require_banker` 鉴权；注入 `X-Api-Key`
- `GET /api/v1/lab-bridge/health`：供前端特征页显示「运行中 / 未连接」
- 注意路由注册顺序：代理必须**排在** `rc_router` 之前，否则请求仍打到旧的同进程实现
- 验收：旧前端 Lab 页一行不改仍可用；`pytest backend/tests` 全绿

### BE-107 · Lab 轻前端静态页（P1，1 天）
- `static/index.html`：46 特征按分类分组、搜索，每条展示 code / 名称 / 单位 / 口径 / 表达式
- `static/try.html`：粘贴 rows JSON 或传 PDF → 提交 → 显示 run_id、可用与不可算清单、结果表
- 页面里 `X-Api-Key` 由用户输入一次存 `sessionStorage`（内网演示级鉴权，代码里要写清楚）
- 验收：`http://127.0.0.1:8030/ui` 能完成一次完整试算，不依赖 npm

### BE-108 · 一键盘集成演示（P0，1 天）
- `POST /api/v1/analysis/features`（业务侧）：上传流水 → 用解析结果调 `submit_run` → 返回 `{task_id, run_id, features:[...]}`
- 报告 payload 里加 `feature_run`（run_id + 取的 code 列表 + 值），**只加新字段，不改既有字段**
- 验收：一份真实建行件走完：上传 → 解析 570 笔 → run_id → 报告能看到 `f_in_total` 等值

### BE-109 · 测试与契约回归（P0，1 天）
- `lab_service/tests/`：契约（字段齐全）、幂等、鉴权 401、超限 413、过期 410、未知 code 404
- 业务侧：`lab_client` 的降级路径（Lab 停掉）
- 兼容代理：旧路径与新服务返回一致（同一份 rows 对比）
- 验收：`pytest lab_service backend/tests -q` 全绿，结果贴 PR

## 六、坑（我踩过，你注意）

1. **路由顺序**：`lab_bridge` 必须在 `rc_router` 前面注册，否则代理永远不生效
2. **rows 里 amount 是字符串**：`Decimal(str(x))`，别转 float；`_rows_from_payload` 已有正确处理，复用
3. **Lab 的 PDF 入口**：`layout_v2` 对真实件抓不到日期列（今天刚修：日期覆盖率 < 50% 用业务解析器兜底），别退回去
4. **run_id 不要用 UUID4**：用内容哈希前 12 位 + 时间戳前缀，便于排查
