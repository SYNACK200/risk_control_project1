# 指标分区与综合评分方案

> 40 项指标按业务域分成 5 个区，每区给一个分数，再加权成总体判断。
> 评分是**可解释扣分制**，不是黑盒模型。

## 1. 五个分区

| 分区 | 指标范围 | 权重 | 说明 |
| --- | --- | --- | --- |
| 收入能力 | A01–A08 | 25% | 收入规模、稳定性、结构、覆盖 |
| 负债与还款 | B01–B08 | 25% | 还款压力、多头借贷、小贷依赖 |
| 资金与余额 | C01–C08 | 25% | 净流入、余额水平与波动、现金使用 |
| 异常行为 | D01–D08 | 15% | 夜间交易、大额支出、博彩/虚拟币 |
| 对手方与集中度 | E01–E08 | 10% | 集中度、关联方、现金支取 |

## 2. 打分规则

1. 每区从 **100 分**起；
2. 该区命中一条风险结论 **−15**（结论到分区有映射表，如 DTI_HIGH→负债、NIGHT_TRADING→异常）；
3. 该区指标缺值（null）**每项 −5**，最多 −20（表示证据不足，而不是没问题）；
4. 分数夹在 0–100；
5. 总分 = 各区分数 × 权重求和；
6. 分档：≥85 良好 / ≥70 一般 / ≥50 关注 / <50 高风险。

## 3. 接口

报告 `payload.scores`：

```json
{
  "overall": 96.5,
  "grade": "good",
  "grade_label": "良好",
  "domains": [
    {"key": "income", "name": "收入能力", "score": 100.0, "weight": 0.25,
     "metric_total": 8, "metric_valued": 8, "missing": 0, "hits": [], "detail": "未见异常"}
  ],
  "method": "分区扣分制：每命中一条风险结论 -15；缺值每项 -5（上限 -20）；按权重加权"
}
```

## 4. 实测（任务 29，招商银行 6 笔）

| 分区 | 分数 | 依据 |
| --- | --- | --- |
| 收入能力 | 100 | 8/8 有值，无结论 |
| 负债与还款 | 100 | 8/8 有值 |
| 资金与余额 | 100 | 8/8 有值 |
| 异常行为 | 90 | 2 项缺值 |
| 对手方与集中度 | 80 | 5 项缺值 |
| **总体** | **96.5（良好）** | 加权 |

## 5. 边界

| # | 边界 |
| --- | --- |
| 1 | 缺值扣分体现“证据不足”，可能让干净但字段少的流水分数偏低 |
| 2 | 权重是暂定值，可按业务调整（改 `algorithm/algo/scores.py` 的 DOMAINS） |
| 3 | 评分不替代人工审批，只是把“哪一区有问题”摆出来 |
