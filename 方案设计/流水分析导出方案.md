# 流水分析页导出方案

> 一句话：导出分三种——**明细 CSV**（给人看/做表）、**完整报告 JSON**（归档/二次分析）、**打印成 PDF**（给审批签字）。

## 1. 三种导出

| 类型 | 入口 | 内容 | 实现 |
| --- | --- | --- | --- |
| 明细 CSV | 报告页「导出明细 CSV」 | 业务号、日期、方向、金额、余额、摘要、对方、页号 | 后端 `GET /tasks/{id}/transactions.csv` |
| 完整报告 JSON | 报告页「导出报告 JSON」 | 报告全文 + 明细 + 版本/阈值版本 | 后端 `GET /tasks/{id}/export.json` |
| PDF | 报告页「打印 / 存为 PDF」 | 当前页面（含四层核验、指标、证据） | 浏览器打印 + `@media print` 样式 |

## 2. 细节

| 项 | 处理 |
| --- | --- |
| CSV 编码 | UTF-8 **带 BOM** + CRLF，Excel 双击不乱码 |
| CSV 顺序 | 按交易日期、id 升序 |
| 文件名 | 用业务号（`T2026….csv` / `.json`），后端 `Content-Disposition` 给出 |
| 权限 | 与其它业务接口一致：Bearer 口令；前端用 `authFetch` 取 blob 再触发下载 |
| 已删除流水 | 回收站内的导出返回 404（不导出已清理数据） |
| 打印 | 隐藏顶栏、按钮、筛选条；卡片与表格行 `break-inside: avoid` |

## 3. 为什么 JSON 而不是 Excel

- 归档要**完整且可解析**：JSON 保留报告结构（层/检查项/指标/结论/证据），Excel 会丢结构；
- 银行要做台账时用 CSV 明细即可；
- 将来要 xlsx 时，可用同一 JSON 再转，不必重算。

## 4. 实测

| 项 | 结果 |
| --- | --- |
| CSV 接口 | 200，`content-disposition: attachment; filename=T2026….csv`，192 行（含表头） |
| JSON 接口 | 200，keys: biz_no/status/carrier/created_at/report/transactions，191 笔 |
| 页面点 CSV | 提示「明细已导出（CSV）」，网络 200 |
| 页面点 JSON | 提示「完整报告已导出（JSON）」，网络 200 |
| 打印 | 走浏览器打印，样式已做（未在自动化里点，避免弹系统对话框） |

## 5. 边界

| # | 边界 | 说明 |
| --- | --- | --- |
| 1 | PDF 依赖浏览器打印 | 服务器端生成 PDF（libreoffice/weasyprint）未做 |
| 2 | 导出无水印、无签名 | 对外出具正式文件需要加水印与签发信息 |
| 3 | 大报告打印可能分页难看 | 目前只做了基本的 avoid-break，深排需专门模板 |
| 4 | 导出不写审计 | 建议补：谁在什么时候导出了哪条流水 |
