# 模板体系整体改进（方案）

> 现状问题不是 UI 丑，而是**匹配规则缺失 + 版本失控 + 信息不落地**。本文按 P0/P1/P2 分级。

## 1. 已确认的问题（都有证据）

| # | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| P0-1 | **银行别名表缺广发** | `BANK_ALIASES` 里没有 `CGB`（grep 计数 0） | 广发件永远识别不出银行 → 建了 CGB 模板也匹配不到 → 任务 113 `template_id=NULL`，只用默认表头解析出 12 笔 |

| P1-1 | 标注页与管理页入口重复、提示互相干扰 | 两处都能建模板 | 用户不知道用哪个 |
| **P0-7** | **行分组容差写死 4pt** | 广发件 12 页、页脚声明 418 笔，只解析出 **12 笔**；容差调到 10pt 后 **265 笔**（页脚一致） | 广发/多方版式几乎全部丢行，报告却给 88.8 分——**假象** |
| P1-2 | 图片件表头 OCR 误读（“交昌日期”）直接失配 | 8 张照片只解析 8 笔 | 拍件场景基本不可用 |

## 2. P0 方案（本次实施）

### 2.1 银行识别补全
`BANK_ALIASES` 扩到覆盖主流银行（广发/华夏/浙商/渤海/恒丰/宁波/上海/北京/江苏/南京/杭州/徽商/长沙/成都/重庆/天津/青岛/苏州/郑州/盛京/锦州/哈尔滨/东莞/三家农商），长名优先匹配。

### 2.2 模板匹配三级（并在结果里写原因）

```
① 显式指定 template_id            → by=explicit
② bank_code + 版式签名相似          → by=layout_signature（表头别名集合 Jaccard ≥ 0.6）
③ bank_code 下唯一 enabled          → by=bank_only
④ 都不满足                          → 无模板，reason 写入 check_result
```
版式签名 = 表头别名（`header_columns` 或 `field_map` 的值）排序后的指纹。

### 2.3 版本与启停
- 新建/外推保存时：`version = 同 bank_code 最大 version + 1`
- 启用某模板：**自动停用同 bank_code 的其它 enabled**
- 只有 `enabled` 参与自动匹配；`draft` 永不自动匹配

### 2.4 预读信息落地
`period_start/period_end`、`account_no`、`account_name` 写进 `task`，报告头显示“统计期间”。

### 2.5 报告可归因
报告展示：`使用模板 #id（银行 X / 版本 v / 匹配方式 Y）` 或 `未使用模板（原因：未识别银行）`。

## 3.5 已实施（本轮）

## 4. 验收标准

| 项 | 标准 |
| --- | --- |
| 广发件 | 能识别为 CGB，并自动匹配 CGB 模板 |
| 版本 | 同银行新建模板 version 递增，且同时只有一条 enabled |
| 归因 | 每个任务都能说出用了哪条模板/为什么没用 |
| 期间 | 任务与报告出现 period_start/end（预读识别到的值） |
