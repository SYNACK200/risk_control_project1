# 多账户合并方案（同一借款人的多份流水如何合成一个视图）

> 版本：v1（2026-10-30）。实现：`algorithm/algo/merge.py`；接口：`GET /api/v1/tasks/merge/modes`、`POST /api/v1/tasks/merge`。
> 说明：本轮未能联网检索（搜索通道未配置），下表方法来自通用的风险加总/凸性聚合/木桶法/证据合成实践，未引用具体文献链接。

## 一、要解决的问题

| 场景 | 直接相加会怎样 |
| --- | --- |
| 两个账户期间重叠 | 月均收入按并集天数算，分母不能简单相加 |
| A 账户转出 1 万、B 账户转入 1 万 | 收入与支出各虚高 1 万（同一笔钱） |
| 一个账户正常、另一个账户有大量小贷 | 平均后异常被稀释 |
| 同一份流水被重复上传 | 全部指标翻倍 |

## 二、七种合并方式

| key | 名称 | 一句话 | 公式 | 适用 | 已知偏差 |
| --- | --- | --- | --- | --- | --- |
| `net_internal` | 合并并抵消内部转账（**默认**） | 去重 + 剔除互转后汇总 | Σ明细 − 重复指纹 − 内部转账成对 | 多账户且可能互转 | 跨行到账延迟 >2 天会漏判 |
| `sum` | 直接相加 | 原样合并 | Σ各账户明细 | 确认无互转 | 互转双记，收支虚高 |
| `dedupe` | 仅去重 | 相同明细只留一条 | Σ明细 − 重复指纹 | 怀疑重复上传 | 不减互转两端 |
| `worst_case` | 最坏情形（木桶） | 每指标取最差 | max（风险类）/ min（稳健类） | 保守审批 | 单账户异常放大到个人 |
| `convex` | 凸性聚合 | 平方和开根，惩罚集中 | √(Σ mᵢ²) | 关心风险是否集中 | 对量纲敏感，比率需先归一 |
| `weighted` | 规模加权平均 | 按流水金额占比加权 | Σwᵢmᵢ ÷ Σwᵢ | 账户重要性差异大 | 小账户异常被稀释 |
| `evidence` | 证据合成 | 真实性置信度在对数几率空间相加 | logit(P)=Σlogit(pᵢ)−(n−1)logit(p₀) | 多份材料合成总体可信度 | 证据不独立时高估 |

## 三、重叠期怎么处理（关键）

| 项 | 规则 |
| --- | --- |
| 期间 | 取各账户期间的**并集**，报告写 `period_start/period_end` 与重叠天数 |
| 月均分母 | 用并集天数的自然月折算，**不重复计月**（沿用指标口径 v2） |
| 内部转账 | 同日或相邻 ≤2 天、金额相等、方向相反 → 成对剔除，`internal_transfers` 列出明细 |
| 单边转账 | 找不到配对的转出/转入不剔除，只在 `notes` 标注「疑似互转未配对」 |
| 余额类 | 不跨账户相加（两张卡余额相加没有业务含义），只保留各账户余额序列用于图形 |

## 四、指标层口径

| 类型 | 处理 |
| --- | --- |
| 流量类（A01 收入、C01 净流入等） | 由**合并后的明细重算**，不手工求和 |
| 比率类（A02、B02、A04…） | `weighted` 加权平均；`worst_case` 取最差；`convex` 平方和开根 |
| 稳健类（A04 稳定性、A06 工资规律月数） | 最坏情形下取 **min**（越小越差） |
| 真实性 | 用 `evidence` 合成，输出总体可信度与最弱账户 |

## 五、给银行人员看什么（简约）

只暴露 3 个选项，其余收进「高级」：

| 界面选项 | 实际方式 | 一句话 |
| --- | --- | --- |
| **合并（推荐）** | `net_internal` | 去掉互转与重复，最接近真实规模 |
| **分开看** | 不合并，逐账户卡片 | 需要定位是哪张卡出问题 |
| **保守估计** | `worst_case` | 按最差账户评价，授信偏严 |

高级里再给 `sum / dedupe / convex / weighted / evidence`，每一项右侧「怎么算」点开显示公式、适用条件、已知偏差（与指标展开同一交互）。
