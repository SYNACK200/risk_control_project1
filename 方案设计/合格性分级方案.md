# 合格性分级方案（合格 / 可授信 / 需补充 / 不合格 / 无法判定）

> 一句话：把原来的「部分合格（有受限）」拆成 **可授信** 与 **需补充**——
> 前者是「我们查不到」，后者是「客户得补材料或系统得复核」。

## 1. 五个等级

| 等级 | 含义 | 典型情况 |
| --- | --- | --- |
| 合格 pass | 四层全部通过 | 载体/内容/账务/外部都 pass |
| 可授信 grant | 核心层没有矛盾、也没有缺项，只是外部数据查不到或存在需留档的小瑕疵 | 外部核验未开通、基线缺失 |
| 需补充 supplement | 缺关键材料，或核心层有单点不合格，或某层未执行 | 缺每页合计/页脚笔数/期初期末余额；字体一致性 fail；内容层没跑 |
| 不合格 fail | 出现一致性矛盾或截图件 | 账务不勾稽、预读与解析不一致、截图 |
| 无法判定 unknown | 没有报告，或图片件无法核验 | 任务失败无报告；扫描图片件 |

## 2. 判定顺序

1. 没有层数据 → 无法判定
2. 某层 inconsistent/fail，或载体是 screenshot → 不合格
3. 载体是 image → 无法判定
4. 四层全 pass → 合格
5. 否则检查核心层（载体/内容/账务）：
   - 有 C2/C3/C4 被跳过（缺每页合计/页脚笔数/期初期末）→ 需补充
   - 有核心检查项 fail/inconsistent（如 F5 字体一致性）→ 需补充
   - 某核心层一项都没执行 → 需补充
   - 以上都没有 → 可授信

## 3. 为什么这么分

| 疑问 | 回答 |
| --- | --- |
| 外部核验没开通为什么可授信？ | 外部数据是「我行查不到」，不是「客户流水有问题」；不应因此要求客户补材料 |
| 字体非嵌入为什么需补充？ | 字体异常会影响「这份 PDF 是不是原件」的判断，属真实性问题 |
| 缺页脚笔数为什么需补充？ | 少了交叉验证依据，银行无法确认解析完整性 |
| 旧报告（无逐项结果）为什么需补充？ | 系统没算过，不能默认没问题；应先重算逐项结果 |

## 4. 接口变化

- authenticity.level 取值：pass / grant / supplement / fail / unknown
- 新增 authenticity.missing_materials：缺哪些材料（如 C2、C3、C4），列表页悬停可见
- facets.authenticity 自动带新等级计数，筛选 chips 变为 5 个

## 5. 实测（当前 15 条）

| 等级 | 条数 | 说明 |
| --- | --- | --- |
| 需补充 | 13 | 绝大多数缺页脚合计/期初期末，或字体一致性 fail |
| 不合格 | 1 | 一致性矛盾 |
| 无法判定 | 1 | 任务失败无报告 |
| 可授信 | 0 | 当前样本没有「核对项齐全且只有外部缺失」的干净件 |
| 合格 | 0 | 没有四层全通过的样本 |

## 6. 单元测试

backend/tests/test_summary.py 共 17 passed，覆盖：全通过、核心通过+外部缺失、核心受限无阻断、缺材料、核心单点 fail、某层未执行、一致性矛盾、空层、截图/图片。

## 7. 边界

| # | 边界 | 说明 |
| --- | --- | --- |
| 1 | 等级由规则给出，不是人工审批结论 | 页面文案应保持「机器判定 + 人工复核」 |
| 2 | C2/C3/C4 是否齐全取决于原件版式 | 有些银行流水本来就不印合计，会一直落在需补充 |
| 3 | 可授信不等于放款 | 只是真实性维度，信用风险仍看风险等级 |
| 4 | 图片件一律无法判定 | 需接 OCR 后才能分级 |
