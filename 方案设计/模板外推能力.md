# 模板外推能力（v0.5.2）

> 目标：模板不只对「完全相同的版式」有效，要能吃下**页面旋转**和**框选偏差**。

## 1. 之前为什么不行

| 问题 | 根因 |
| --- | --- |
| 旋转页建不了模板 | 「标注外推」用 pdfplumber 取词（原始坐标），而界面标注点在**显示坐标**（旋转后）；两套坐标系差 90°，标注点附近找不到任何词 |
| 框选偏一点就失败 | 就近吸附半径写死 40pt、列聚类容差写死 14pt，与页面尺寸无关 |
| 吸错列也被判通过 | 越界时吸到页眉词（卡号/起止日期），反验只查余额链，偶发漏判 |

> 注：**解析**侧一直是好的——parse.py 早就乘了 rotation_matrix，所以工行那份旋转件能解析出 191 笔。

## 2. 现在的做法

| 能力 | 实现 |
| --- | --- |
| 旋转归一化 | infer._words() 改用 pymupdf，词坐标统一乘 page.rotation_matrix，与界面标注、与 parse.py 同一套坐标 |
| 偏差吸附（三级） | ①欧氏距离 ≤2.5% 页宽；②同列（横向 ≤6% 页宽、纵向 ≤15% 页高）；③仅横向最近（≤12% 页宽） |
| 容差自适应 | 吸附半径、列聚类容差都按页宽计算（最小 10pt / 24pt），不再写死 |
| 页眉词过滤 | 「卡号/户名/起止日期/申请单号/打印/第/共/页…」前缀词在所有吸附级别都被排除，不会被当成列 |
| 反验兜底 | 余额链、金额可解析率对不上 → valid=false 并给出原因，不产出错误模板 |

## 3. 实测（真实工行件，8 页，旋转 90°，需口令）

| 场景 | 结果 |
| --- | --- |
| 精确标注 4 列 | **valid=true**，映射 交易日期/摘要/收入支出金额/余额 全对 |
| 偏差 +25pt / −20pt | valid=false，原因「余额链 190 处可核对、189 处不符」——被反验明确拒绝 |
| 偏差 −30pt / +15pt | valid=false（吸附不到有效列，缺必需字段）——不会生成错模板 |

## 4. 当前能力边界（要如实说）

| 边界 | 说明 |
| --- | --- |
| 旋转 | 90/180/270 均已归一化（本次验证的是 90°） |
| 偏差容忍 | 实测 ±15pt 左右可靠；**±25pt 以上会失败**（失败是安全的：明确拒绝，不会产出错模板） |
| 更大偏差的下一步 | 按「列内容语义」选列（日期列/金额列/余额列各自特征），而不是单点吸附；预计可把容忍度提到 30–40pt |
| 表头缺失的版式 | 仍依赖「必需字段能被推断」；表头文字全无时会退化为数值列推断 |
