## 2. 解析四层金字塔（现在的实现）

| 层 | 触发条件 | 实现 | 实测 |
| --- | --- | --- | --- |
| L0 模板解析 | 银行已建模板且启用 | `template.field_map` 按列号取值 | 工行样本 191 笔 |
| L1 自动匹配 | 无模板但有银行名 | 预读识别银行 → 找同 `bank_code` 的启用模板 | 本任务识别为建行，但库中无建行模板 → 跳过 |
| L2 pdfplumber | PyMuPDF 抽不到 | 换引擎重试 | 本任务仍 0 笔 |
| L3 通用解析（默认模板） | L0–L2 全失败 | 表头驱动：找表头行 → 按列中心切列 → 逐行落列 | **本任务 570 笔** |
| L4 OCR | 无文字层 | `_parse_ocr`（需 OCR 依赖） | 未在本次验证 |

通用解析的规则（不猜）

1. 表头别名表：日期/摘要/收入/支出/金额/余额/对方/渠道；命中 ≥2 个才算表头。
2. 行重组：横排按 y 聚类、竖排（旋转 90°）按 x 聚类。
3. 日期三种写法：`2021-05-13`、`2021/05/13`、`20210513`。
4. 方向：收支列 → 正负号 → 相邻行余额变化（容差 2%）。
5. 认不出的列**不猜**，写进 warnings 交人工核对。

## 3. 银行侧能做什么

| 能力 | 入口 | 说明 |
| --- | --- | --- |
| 看解析怎么失败的 | 报告页「识别自检」+ warnings | 现在会明确写「回退表头驱动的通用解析」 |
| 换模板重解析 | 报告页「解析模板」下拉 + 重新解析 | 可选任意启用模板，或无模板（通用解析） |
| 开绿灯 | 报告页「开绿灯（人工放行）」 | 填理由，写审计，页面显示白名单横幅 |
| 建模板 | 模板标注 / 模板管理 | 版式固定后建模板，下次 L0 直接命中 |

## 4. 白名单（绿灯）的语义

- 白名单**不修改**任何核验结论（载体/内容/账务/外部照旧），只标记「已人工复核」。
- 列表页显示 `白名单` 标签，报告页显示横幅与理由、时间。
- 后续使用：解析失败不再阻断（例如合并、导出），但结论仍如实呈现。
- 审计：每次开绿灯写 `AuditLog(action=whitelist_task)`。

## 5. 已知限制

| # | 限制 | 影响 |
| --- | --- | --- |
| 1 | 通用解析对「多行折行单元格」未做合并 | 对方名称可能截断 |
| 2 | 页脚笔数校验在通用解析下不生效（页脚本身是乱码数字） | 少一道交叉验证 |
| 3 | 自动匹配只看银行名，未做表头指纹 | 同银行多版式时可能选错模板 |
| 4 | 通用解析的结果标记为 partial（解析质量不完整） | 需人工核对 1–2 页 |
