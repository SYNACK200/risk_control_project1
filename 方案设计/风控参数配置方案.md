# 风控参数（超参）配置方案

> 一句话：**阈值是银行的可调超参，不是代码里的常量；改一次生成一个版本，旧报告不重写。**

## 1. 为什么单独做一页

| 现状问题 | 本方案 |
| --- | --- |
| 23 个阈值写死在 `thresholds.py`，改一个要发版 | 页面可改，保存即生效（新受理与重解析） |
| 不同银行风险偏好不同（保守/激进） | 每家银行一套参数，带版本历史与审计 |
| 改了参数说不清哪份报告用了哪版 | 报告记录 `threshold_version`，可追溯 |

## 3. 版本规则

1. 初始版本 = 算法默认 `THRESHOLD_VERSION`（当前 2）。
2. 每次保存 → 版本号 +1，写 `threshold_profile` 并记审计（`save_thresholds`）。
3. **报告只记录使用时的版本**：`report.threshold_version`，旧报告不重算、不改变。
4. 重解析按**当前生效版本**计算，会生成新的报告版本。
5. 恢复默认也生成新版本（不是删除历史）。

## 4. 校验（两道）

| 层 | 规则 |
| --- | --- |
| 前端 | 必填（HHI 可为空）、数字、min/max、整数类提示 |
| 后端 | `validate_values`：未知键拒绝、类型、范围；缺参数拒绝；400 + 中文原因 |

## 5. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/thresholds` | 当前版本、参数值、默认值、定义表、历史 |
| PUT | `/thresholds` | 保存新版本（body: values, note） |
| POST | `/thresholds/reset` | 恢复算法默认（也是新版本） |

全部要求 `Authorization: Bearer $LOCAL_ACCESS_PASSWORD`（与 BE-20a 一致）。

| 操作 | 结果 |

## 7. 边界

| # | 边界 | 说明 |
| --- | --- | --- |
| 1 | 只影响阈值判定，不改指标口径 | 指标口径升级仍是 `METRIC_SET_VERSION` |
| 2 | 不按银行/产品分行配置 | 现在是全局一份；多租户需加 `bank_code` 维度 |
| 3 | 未校准项仍标「未校准」 | 5 个参数默认值待业务确认 |
| 4 | 没有审批流 | 目前保存即生效；若要双人复核需加 draft/approve 状态 |

| 阈值 | 结论 |
| --- | --- |
| 旧 0.50 | **无** DTI_HIGH |
| 新 0.40 | **命中** DTI_HIGH |

### 回滚

1. 页面上「恢复默认」→ 回到算法默认（不是 v5）；
2. 精确回滚 v5：`PUT /thresholds` 提交 v5 的 values（本次变更前的值已导出备份）；
3. 旧报告保留自己的 `threshold_version`，不因新阈值改变。
