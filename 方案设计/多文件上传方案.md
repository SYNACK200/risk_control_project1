# 多文件上传方案（v0.6.0）

> 支持两种真实场景：① 一次提交多份流水；② 同一份流水的多张照片/扫描页。

## 1. 两种模式

| 场景 | 前端表现 | 后端行为 |
| --- | --- | --- |
| 多份流水（含 PDF） | 列出全部文件 | 每个文件**分别**受理，生成多条任务（复用 `POST /tasks`） |
| 同一份的多张照片（全图片） | 提示「会按顺序合成一份材料」 | 调 `POST /tasks/compose`，合成一个 PDF 后按单份受理 |

判定规则：所选文件**全部是图片** → 合成；**含任何 PDF** → 分别受理。

## 2. 合成实现（`POST /tasks/compose`）

| 输入 | 处理 |
| --- | --- |
| PDF | 原页按顺序拼接（有口令先解密，解密失败返回 `E_ENCRYPT`） |
| JPG/PNG | 等比缩放进 A4（595×842），居中，四周留 12pt |

限制：一次最多 20 份、总大小 ≤ 80MB；合成后再走原有受理链路（预读 → 模板匹配 → 队列 → 解析）。

## 3. 实测

| 检查 | 结果 |
| --- | --- |
| 两份 PDF 合成（各 6 笔 / 5 笔） | 生成 1 条任务，状态 `DONE`，明细 **11 笔**（相加正确） |
| 前端构建 | `tsc` 通过、`build-app` 成功 |
| 单文件路径 | 保持原行为（仍显示单文件卡片、直接跳进度页） |

## 4. 边界

| # | 边界 |
| --- | --- |
| 1 | 合成只支持 PDF 与图片；其他格式（xls、doc）仍拒绝 |
| 2 | 图片按 A4 单页摆放，超长截图会被压缩（可能影响 OCR 清晰度）；拍照件结论仍封顶「无法判定」 |
| 3 | 分别受理时前端**串行**提交，10 份以上会较慢（后端已是队列模式，可改并发 2–3） |
| 4 | 分别受理没有「批量进度页」，只在顶部列出各任务号，逐个点开看进度 |
