# 一、这一层承担什么

回答两个业务问题：**这份材料可不可信**、**这个人账上什么情况**。

与以前不同的两点：

| 以前 | 现在 |
| --- | --- |
| 只呈现，不判断 | **按默认阈值给结论**，银行可改阈值，改了记版本 |
| 指标固定 40 项 | **指标集可增减**，每版有编号 |

## 一句话原则

> 结论要有依据，依据要能回到原页；判不了就说判不了，不许猜。

# 二、整体验证链（一条主线，八个环节）

```text
收件 → ①载体判定 → ②抽取 → ③抽取自检 → ④内容核对 → ⑤账务核对 → ⑥外部交叉 → ⑦阈值判定 → ⑧出结论与证据
         │            │           │            │            │            │
         └─ 判不了 ────┴─ 置信低 ──┴─ 先归因 ───┴─ 无利率表 ─┴─ 无授权 ─────┘
                                        ↓
                                   降级或转人工
```

每个环节的规则：

| 环节 | 输入 | 判定依据 | 分支 | 记录 |
| --- | --- | --- | --- | --- |
| ① 载体判定 | 文件字节 | 是否 PDF、能否提取文字、是否有截图特征 | 电子件 / 影像件 / 截图件 | 判定结果与依据 |
| ② 抽取 | 文件 + 模板 | 行内 OCR 服务返回的坐标与置信度 | 成功 / 部分成功 / 失败 | 每行置信度 |
| ③ 自检 | 明细 | 完整率、平均置信度、低置信行占比 | 达标 / 不达标重跑 / 转人工 | 三项数值 |
| ④ 内容核对 | 明细 | 四类算术等式 | 通过 / 失败（先归因） | 失败行号与差额 |
| ⑤ 账务核对 | 明细 + 利率表 | 复算利息 | 吻合 / 偏差 / 不可算 | 复算值与偏差 |
| ⑥ 外部交叉 | 明细 + 外部数据 | 与第三方记录一致性 | 一致 / 不一致 / 无授权 | 用了哪些外部源 |
| ⑦ 阈值判定 | 指标 + 阈值版本 | 默认或银行自定义阈值 | 触发 / 未触发 | 阈值项与取值 |
| ⑧ 结论与证据 | 以上全部 | 组合规则（见第七节） | 五态之一 | 证据坐标 |

**关键设计：③④⑤ 任何一环不通过，都要先回答「是我们错了还是材料错了」**，回答不了就不许下结论。

# 三、载体层：两条独立的验证路

## 电子件（结构取证 11 项，按成本从低到高）

| 组 | 项目 | 串起来回答什么 |
| --- | --- | --- |
| 第一组：文件怎么生成的 | 生成器指纹、创建与修改时间、增量更新痕迹、结构指纹 | 是不是银行系统一次导出的 |
| 第二组：排版是否被改过 | 字体一致性、隐藏文字层、覆盖图元、版面一致性 | 数字区域有没有被动过 |
| 第三组：整体是否异常 | 签名与时间戳、体量与页密度、图像混排 | 有没有整页替换或重排 |

组合规则：

| 命中情况 | 判定 | 处置 |
| --- | --- | --- |
| 第一组任一项命中 | 来源可疑 | 停止，要求官方原件 |
| 第二组两项以上命中 | 来源可疑 | 停止，指出页码 |
| 第二组仅一项命中 | 记录但不阻断 | 继续，报告标注 |
| 第三组命中 | 记录 | 计入受限说明，不单独定性 |

为什么第一组一票否决：生成方式不对，后面所有数字都没有意义。

## 影像件（图像取证 8 项，靠组合）

| 组合 | 判定 | 理由 |
| --- | --- | --- |
| 二次压缩 + 屏幕摩尔纹 + 边缘涂改 同时出现 | 来源可疑 | 三项同现基本只能是人为加工 |
| 拼接与复制 + 版式对齐异常 | 来源可疑 | 局部被替换 |
| 仅 EXIF 缺失 | 记录不阻断 | 社交软件转发会清空，属常见现象 |
| 仅光照不均 | 记录不阻断 | 拍摄本身就可能不均 |
| 全部无命中 | 未发现异常（核验受限） | 图片无法排除打印后涂改 |

**影像件的结论永远带限制句**，这不是保守，是事实：图片无法证明它不是「打印—涂改—再拍」。

## 截图件

不做逐项取证，只做三件事：确认是截图、抽取、核对内容。
结论直接封顶为**来源可疑**，且报告写明不得作为授信依据。理由：截图可以完美伪造，且无法证明来源。

### 统一口径

- `fail` 只给三处客观事实：C5 同一可比字段对不上；C6 同一参考号出现在两笔不同明细；C10 同组且参考号相同。其余命中一律 `hint` 或 `skipped`。
- `hint` 不改变内容层状态，也不参与五态；报告 limitations 追加「提示（不影响结论）：…」并列出可回指的行。实现时 `CheckStatus` 增加 `hint`；不因提示把内容层判成 `inconsistent`。
- `skipped` 必须写原因，且不得显示为「通过」。缺字段、低置信、掩码导致的不可比都走这里。
- 证据一律带 `page_no`、`row_no`、`bbox`；拿不到坐标时写页码与行号，并注明「缺坐标」，不编造。
- 每项检查带 `rule_version`，v1 均为 1。C8 从「只出统计」升级为「带提示线」、C9 规则增删都要升版本；旧报告按当时版本解释，不回写。版本现记在 `CheckResult.rule_version`；报告目前只透出层结论，若要在报告里显示到检查级，需 PM/PD 补契约字段。
- 适用范围：电子件优先；影像件字段置信度 <0.80 视同未识别清，C5/C6 会更多走 `skipped`，不得降级为 `pass`。

### 当前字段可得性

2026-10-31 起页眉字段（账号/户名/期间）与参考号字段（`Transaction.reference_no`，别名含流水号/交易流水号/凭证号/业务编号/交易单号/交易编号，不含「序号」）都已随解析抽取，C5–C10 全部接入真实字段。三份脱敏真件里：工行无参考号列、有 `trade_time`；招行有摘要/金额/对手方（对手方整列打码）但无参考号、无交易时间；微信 0 笔。因此 C6 在真件上多为 `skipped`；C6/C10 的 fail 分支已由样本集 v3 的同参考号复制件端到端覆盖（eval 9/9），含参考号的真件到位后仍需复核。

C5 的分级按字段落地：至少一项字段跨页可比且一致、另有字段缺失或掩码不可比 → `partial`（detail 写清已核对项与不可比原因）；所有页眉字段都不可比 → `skipped`；任一项可比字段对不上 → `fail`。不因掩码字段把整项判成 `pass`。

## 失败时的归因链（这一环最容易被跳过）

```text
余额链失败
   ↓
看该行抽取置信度
   ├─ 置信度低（< 0.8） → 判「识别错误」→ 回②重跑；重跑仍低 → 转人工
   └─ 置信度正常     → 判「数据断」→ 内容层定性「存在不一致」→ 停止出报告
```

**为什么必须分开**：识别错误是我们的问题，数据断是材料的问题。混在一起，用户会收到一句他没法处理的「校验失败」。

# 五、账务层：结息反算的逻辑

## 什么时候能算

| 条件 | 说明 |
| --- | --- |
| 明细里有明确的利息或结息记录 | 没有就不可算 |
| 有该行该产品的利率表 | 没有就不可算 |
| 结息周期完整落在考察期内 | 跨期的只算落在期内的部分 |

## 怎么算

```text
按日终余额累加积数 → 乘日利率 → 得应得利息
日利率 = 年利率 ÷ 基准天数（360 或 365，由利率表给）
应得与实际比较，容差 0.05 元
```

## 偏差怎么解释

| 情况 | 判定 | 报告怎么写 |
| --- | --- | --- |
| 偏差 ≤ 0.05 | 吻合 | 结息复算一致 |
| 偏差 > 0.05 | 余额可疑 | 复算 X 元，实际 Y 元，差 Z 元 |
| 利率表缺该产品 | 不可算 | 未取得该产品利率，本次未做结息复算 |
| 明细无利息记录 | 不可算 | 该账户考察期内无结息 |

## 为什么这层最值钱

造假者要过这一关，得知道这家行的利率、计息方式、结息日，还得把整段余额历史重算一遍。**成本远高于改几个数字。**

# 六、交叉验证（真实性判断的核心）

单一证据都能伪造，**两路独立方法指向同一事实才算证据**。四条交叉链：

| # | 链 | 两路方法 | 一致说明什么 | 不一致说明什么 |
| --- | --- | --- | --- | --- |
| X1 | 明细内部 | 余额链 vs 合计行 + 笔数 | 内部自洽 | 至少有一处被改动，先归因再定性 |
| X2 | 账务外部 | 结息复算 vs 明细里的利息记录 | 材料符合该行记账规则 | 有人重排过这份流水 |
| X3 | 抽取质量 | OCR 返回 vs 本地结构解析（电子件） | 抽取可信 | 抽取有误，先重跑，不许当材料问题 |
| X4 | 载体与内容 | 载体取证 concl vs 内容自洽 | 两条独立路径都干净 | 一条脏一条干净 = 高度可疑 |

## 交叉验证的判读表

| X1 | X2 | X3 | X4 | 结论 |
| --- | --- | --- | --- | --- |
| 一致 | 一致 | 可信 | 干净 | 未发现异常 |
| 一致 | 一致 | 可信 | 有痕迹 | 来源可疑 |
| 不一致 | — | 可信 | — | 存在不一致 |
| 不一致 | — | 不可信 | — | 先重跑，重跑后仍不一致才算材料问题 |
| — | 不一致 | 可信 | — | 余额可疑 |
| — | 不可算 | 可信 | 干净 | 未发现异常但核验不完整 |

**X3 的意义**：很多人把抽取错误当成材料造假。这一条链就是用来防这个的——先证明我们抽对了，再谈材料对不对。

# 七、阈值与结论（阈值的口径与默认值由算法组定义，后端只存与暴露，前端只展示与提交修改）

## 默认阈值（系统发布时自带，银行可改；v2 共 13 项）

| 项 | 条件 | 默认 | 越界后提示什么 |
| --- | --- | --- | --- |
| DTI_HIGH 债务收入比 | B02 ≥ 阈值 | 50% | 月供压力偏高 |
| INCOME_UNSTABLE 收入稳定性 | A04 ≥ 阈值 | 0.5 | 收入波动大 |
| LOW_BALANCE 最近 30 天最低余额 | C06 < 月供 × 倍数 | 当地月供 1 倍（缺数据用 B01 近似） | 流动性偏紧 |
| MULTI_LOAN 网贷平台数 | B04 ≥ 阈值 | 3 个 | 多头借贷迹象 |
| GAMBLING_HIT 涉赌命中 | GAMBLING 标签笔数 ≥ 阈值 | 1 笔 | 存在敏感交易 |
| NIGHT_TRADING 夜间交易 | D02 > 阈值 | 10% | 交易时段异常（缺 `trade_time` 不触发） |
| NET_OUTFLOW 净流出 | 净流出且占流入 ≥ 30%，或连续 2 个月净流出 | 30% / 2 个月；单月下限 100 元（未校准） | 资金持续外流 |
| BALANCE_DECLINE 余额下降 | 月均余额降 ≥ 10% 且期末余额低于月供线 | 10% + 1 倍月供 | 余额趋势恶化 |
| FAST_IN_OUT 当日进出 | 占比 > 0.2 且当日进金额 ≥ 下限且有效笔数 ≥ 3 | 0.2 / 500 元（未校准）/ 3 笔 | 快进快出迹象 |
| COUNTERPARTY_CONCENTRATED 对手方集中 | 有效对手方笔数 ≥ 20 且 HHI ≥ 校准阈值 | 未校准（暂不判定，只告警缺失率） | 对手方高度集中 |
| NEW_LOAN 新增贷款 | 近 6 月放款 ≥ 1 笔且金额 ≥ 月均收入 30% | 1 笔 / 30%（未校准） | 新增负债 |
| SMALL_LOAN_REPAY 小贷还款 | 月均 ≥ 1 笔 | 1 笔/月 | 小贷使用迹象 |
| CRYPTO_HIT 涉币交易 | ≥ 1 笔且金额 ≥ 下限 | 1 笔 / 1000 元（未校准） | 涉币交易线索 |

「未校准」= 算法组暂定默认值，须按「修口径与缺失值 → 样本分布校准 → 按误报代价定价」确认后定稿；确认前照常输出并在报告中注明。SALARY_IRREGULAR（工资规律）依赖代发账户识别，未实施。

统计口径：净流出连续性按自然月补零，缺交易月中断连续；余额下降的期末余额取最后一个月内日期最新一笔（同日按行序），文件按时间正序；涉币有规则命中时按 `CRYPTO` 标签，否则按摘要词库；对手方为纯掩码名称时单独告警。

规则：

1. 给的是**结论提示**，不是评分，也不构成放款建议；全部 `level=info`，不聚合为综合风险等级。
2. 阈值结论本质是线索：命中标签（网贷、涉赌、虚拟币）只影响提示与排序，不改变真伪结论。
3. 银行改阈值后，结论重算，但**老报告不重写**，按当时阈值解释。
4. 每次结论记录 `threshold_version`，报告里可查。
5. 阈值只影响「提示是否触发」，**不影响真伪结论**——材料真假由第四、五、六节决定。

## 五态结论怎么合

| 前置 | 结论 | 处置 |
| --- | --- | --- |
| 载体层来源可疑 | 来源可疑 | 停止，退回原件 |
| 内容层存在不一致（归因为数据断） | 存在不一致 | 停止，指出行号 |
| 账务层偏差超容差 | 余额可疑 | 停止，写明复算与差额 |
| 有一层不可算或无授权 | 未发现异常（核验受限） | 继续，报告写明哪层没做 |
| 全部通过 | 未发现异常 | 继续 |
| 抽取失败且重跑无效 | 无法判定 | 转人工 |

# 八、指标集的增减规则

| 动作 | 谁来定 | 影响 |
| --- | --- | --- |
| 新增指标 | 银行提需求，PM/PD 定口径 | 指标集版本 +1 |
| 改口径 | 口径有争议或监管要求 | 单项 caliber_version +1，指标集版本 +1 |
| 停用指标 | 连续两个版本无人使用 | 标记停用，不删历史值 |
| 改名 | 仅显示名变更 | 不升版本，记录变更 |

硬规则：**历史报告里的指标值永远按写入时的版本解释，不因新版本而变。**

# 九、失败与降级矩阵

| 失败点 | 影响 | 降级方式 | 用户看到什么 |
| --- | --- | --- | --- |
| OCR 服务不可用 | 无法抽取 | 任务失败，可重跑 | 识别服务暂不可用，请稍后重试 |
| 模板缺失 | 版式不认识 | 走通用解析，准确率下降 | 该版式未收录，结果需人工核对 |
| 利率表缺失 | 账务层不可算 | 标注核验不完整 | 未取得利率，本次未做结息复算 |
| 外部数据无授权 | 外部层不可用 | 标注未做 | 外部核验未开通 |
| 无真件基线 | 结构指纹弱化 | 只做单点判断 | 无同行基线，结构比对受限 |
| 置信度整体偏低 | 明细不可靠 | 转人工 | 识别质量不足，已转人工处理 |

# 十一、不做

| 不做 | 为什么 |
| --- | --- |
| 出评分、等级、放款建议 | 放不放款是银行的决定 |
| 断言材料为真 | 我们不是鉴定机构，只能说未发现矛盾 |
| 用生成式模型补数值 | 数值必须可复现 |
| 判模板能不能正确识别 | 模板由银行维护 |
| 把命中线索当证据定性 | 线索只提示，不定性 |
