# AL-36 模板外推反验

## 意图

`infer.py` 只凭标注推列、按统计猜语义，推错也照样返回模板；错模板一旦落库，
后面所有解析都会按错的列读，且报告里看不出来。本轮加一道反验：
用推断出的模板真解析一遍，对不上就只给 warnings、不出模板。

## 结论

反验放在 `infer_template()` 末尾，规则全部来自已有结构关系，不引入新阈值：

| 条件 | 判据 |
| --- | --- |
| 必需字段齐全 | `txn_date` / `amount` / `balance` 都能推断出（原先只告警，现在拒绝） |
| 能解析出明细 | 解析笔数 > 0 |
| 行数守恒 | 有页脚声明时，解析笔数与声明一致（复用 `parse()` 的 `footer_count`） |
| 金额/方向可取 | 过半笔数取不到金额或收/支方向 → 列映射可疑 |
| 余额链闭合 | 可核对 ≥2 处且全部不符，或 ≥5 处且不符超过 20% → 金额/余额列可能颠倒 |

顺带修出一个真 bug：`apply_template()` 是「合并」而不是「覆盖」，模板显式把
`amount` 指到摘要列时，表头自动识别的「交易金额」仍留在映射里，同一字段挂了两列，
`line_cells` 把两列文字拼成一个单元格，金额被拼出 `工资 12,500.00` → 12500.00，
反验因此一度放行。改为模板显式映射优先、同一字段只留模板指定那列。

## 改动

- `ocr/infer.py`：新增 `_validate()`；`InferResult.template` 可为 None，新增 `valid` 属性；
  反验不过时追加「反验未通过，未生成模板；请修正标注后重试」。
- `ocr/table.py`：`apply_template()` 改为覆盖同一字段的自动映射。
- 后端：`infer_from_marks()` 返回 `valid`，模板为空时 `field_map` 给 `{}`；
  `/templates/infer` 只在 `valid=true` 时保存草稿。
- 前端：`InferResult` 加可空 `valid`；反验不过时隐藏「保存为草稿」。
- 测试：新增 `tests/test_infer.py` 4 个用例（正确标注、金额余额对调、金额标到摘要列、缺必需字段）。

## 验证

- `pytest algorithm/tests -q` → 186 passed（原 182 + 4）。
- 真实工行件只标 交易日期/收入支出金额/余额 三处表头：`valid=True`，
  `field_map={'txn_date': '交易日期', 'amount': '2收入/支出金额', 'balance': '余额'}`，无 warnings。
- 同一文件把金额、余额两处标注对调：`valid=False`，报「余额链 … 全部不符」且不出模板。
- 工行件 `local_run.py` 回归：40 项指标数值逐项比对无差异，结论与自检状态不变。

## 遗留

- 锚点吸附半径 40 pt 偏大：标在表头边缘时会吸到页眉碎字（实测 x=410 吸到 `C`，
  改到 x=440 才落在「收入/支出金额」上）；是否需要收紧或按列内文字校验，待标注页联调时再定。
- 表头别名会带噪声（实测别名是 `2收入/支出金额`），能匹配是因为解析侧同一串也带 `2`；
  若原件版式变了会失配，属 AL-34 模板转换层要处理的问题。
- 前端未跑构建：本机无 `node_modules`，`valid` 字段的界面行为只做了代码层改动，未在浏览器验证。

## 裁决

无契约变更；模板格式、报告结构、阈值都没动。
