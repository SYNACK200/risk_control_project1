# local_run 摘要：受限清单截断处补剩余条数

## 意图

演示彩排发现 `algorithm/local_run.py` 的摘要只打印 `limitations[:10]`，工行件实际
29 条，E1–E7「未启用原因」等全被截掉且没有任何提示，看摘要的人会以为报告里没有
这些限制。完整清单一直在报告 JSON 里，问题只在摘要的呈现。

## 改动

- `algorithm/local_run.py`：新增 `SUMMARY_LIMITATIONS = 10` 与
  `summary_limitations(items)`——前 10 条照常列，超出时追加一行
  「……其余 N 条见报告 JSON 的 limitations（共 M 条）」；摘要「受限」改用该函数。
- 测试：`tests/test_local_run.py` 新增 `test_summary_limitations_only_truncates_with_count`，
  覆盖不截断（原样返回）与截断（11 项、末行为剩余条数）两种情形。

## 验证

```
./.venv/Scripts/python.exe -m pytest algorithm/tests -q
# 252 passed, 5 warnings

./.venv/Scripts/python.exe algorithm/local_run.py algorithm/inputs/samples/icbc_desensitized.pdf \
  --template algorithm/integration/samples/icbc_template.json
# 摘要「受限」11 条：前 10 条 + 「……其余 19 条见报告 JSON 的 limitations（共 29 条）」
```

## 遗留

- 只改摘要呈现，不动 `limitations` 生成与报告 JSON；顺序与内容不变。
- 摘要仍是「前 10 条」的固定窗口，若演示希望按层分组（F/C/A/E）展示，需要另定格式。

## 裁决

- 截断可以，但不能无提示；摘要给条数与去向，完整内容以报告 JSON 为准。
- 本轮改动留在工作区，未提交、未推送、未 `git pull`。
