# 招行真件落地与 AL-47 方向识别

## 意图

拿到本人招商银行借记账户流水（2 页 30 笔，带口令），要求先脱敏再验证版式匹配
（组长此前已按该版式做过匹配）。验收目标是 AL-47：招行样本 A01 能算出且与人工一致（约 1.8 万）。

## 结论

脱敏件已入 `inputs/samples/cmb_desensitized.pdf`（samples 目录 git 忽略）。解析 30 笔，
A01=17957.03，与按明细逐笔手算一致；S6 余额链 29 处全闭合，S7 方向 0 缺失，总结论「未发现异常」。

过程中查出四个真实缺陷，都会影响真件、不只影响这一份：

| 缺陷 | 现象 | 根因 |
| --- | --- | --- |
| PyMuPDF 主引擎整流丢词 | 招行两页都「未识别到表头」，被迫回退 pdfplumber | `get_text("dict")` 的块号含图像块，`get_text("words")` 的块号不含；招行 logo 排在正文前，编号整体错位 1，按行号取正文全部落空 |
| 续页顶边距误判 | F9 fail → 总结论「来源可疑」 | F9 用全页最小文字 y 当顶边距；续页不重复抬头、直接从表头起排，天然低 9.8 pt |
| 页脚并入末笔 | 末行摘要被拼上「温馨提示…」、对手方被写成页码 | 日期缺失的续行一律并入上一笔，未限制与上一行的垂直距离 |
| 方向缺失 | 11 笔无符号金额 direction=null，A01 只能给 null | 只认「收支列 / 收入支出两列 / 负号」，没有处理「有符号金额列里未带负号=入账」的约定 |

## 改动

- `ocr/parse.py`
  - `_fitz_page_words()` 改为按几何位置判断正文：词框与「字号在 5–12pt 内的 span」交叠面积占比 ≥ 0.5 才收，
    不再依赖块/行编号；按 y 排序 + 二分缩小候选，3000 笔量级仍是一次线性扫描。
  - 新增 `_fill_signed_directions()`：整表既无方向列、也无收入/支出两列，且金额列出现过负数时，
    未带负号的行补为入账，补判笔数写进 warnings；列内没有负数不推断。
  - 续行并入上一笔前检查与上一行底边的距离（`CONT_MAX_GAP = 24`），页脚不再污染末笔。
- `ocr/table.py`：表头别名补「对手信息」→ counterparty（招行表头用词）。
- `algo/file_layer.py`：F9 改为比页尺寸、旋转、左边距；顶边距只在起始行相同的页之间比，
  起始行不同的页在 detail 里注明未比对；右边距、下边距随内容长度变化，不作判据。
- 测试：`tests/test_parse.py` 新增 5 例（符号补方向、无负数不推断、有方向列不推断、远处页脚不并入、
  图像块在前仍走 PyMuPDF）；`tests/test_file_layer.py` 新增 3 例（续页通过、同抬头位移 fail、左边距位移 fail）。

- `pytest algorithm/tests -q` → 194 passed（原 186 + 8）。
- 招行脱敏件 `local_run.py`：2 页、30 笔、覆盖 2026-08-30~10-16；A01=17957.03、A02=11360.89、
  C01=8.33；S1/S2/S3/S4 30/30、S6 pass（0 处不符、0 笔跳过）、S7 pass；四层 file/content/ledger = limited，
  结论「未发现异常」。对照手算：入账 1850+101+1300+1+100+200+0.03+5+1000+400+13000=17957.03，
  出账 17948.70，期末余额 8.33，三项都对得上。
- 工行真件回归：与 HEAD 版本报告逐项比对，40 项指标 0 差异、自检与 limitations 完全一致。
- 微信件不变：0 笔、无法判定。

## 遗留

- 组长的版式匹配件 `integration/samples/cmb_template.json` 是 v2 箱体格式（`meta_boxes`/`tables`/`match_rule`），
  `Template` 模型只有 `field_map`，`parse()` 不消费这些键；当前招行解析靠通用表头识别（补了「对手信息」别名）。
  要把箱体模板变成解析输入，属 AL-34 模板转换层，未做。
- 脱敏件把对手信息整列抹除，E01/E02 返回 null；真实集中度需在本机用原件核验后再删。
- F9 判据变更（顶边距条件化、不比右/下边距）属于取证口径调整，需组长确认后写进 design。
- AL-43 的 S4 判据是否改按行比对仍未定，工行件 S4 依旧 limited。
- 前端未验证：本轮只动算法侧。

## 裁决

- 本人 2026-10-30：招行脱敏件只保留日期/金额/余额/摘要，户名、账号、开户行、验证码打码，
  对手信息整列抹除（不留占位名，避免把掩码当成同一对手方把集中度做成假信号）。
- 本人 2026-10-30：方向判定采用「收付列 → 收支两列 → 金额符号」的优先级；符号推断要求整表无方向列
  且金额列出现过负数，避免只有进账的流水被误判；补判笔数必须写进 warnings，供人工复核。
- 契约、阈值、报告结构均未改动。
