# 低置信留痕、未校准注明、S4 排查工具 v2 兼容、样本集扩到 8 份

## 意图

AL-43 之后清一遍未完成项，只做不依赖外部数据、不改口径的收尾：

1. 低置信明细此前会被静默计入指标与结论，审批人看不到「这行读数不可靠」；
2. `diagnose_s4.py` 只认旧版 `field_map` 模板，招行 v2 箱体模板要先手工转换；
3. AL-15 只有两类伪造，design V1 要求的删行、拼页已具备造样条件；
4. 未解析到明细时，五态「无法判定」的原因取首个 skipped 检查（C1 无可用余额行），
   没有说明真正原因；
5. design.md:195 要求未校准值在报告中注明，但触发未校准项时报告看不出是暂定值。

阈值、S4 判据、指标口径、结论规则均未改动。

## 改动

- `algo/report.py`：新增 `_low_confidence_limitation()`，明细中存在
  `Transaction.confidence < LOW_CONF (0.80)` 时，limitations 写明笔数与涉及页；
  相关行仍按识别值计入指标与结论，不排除、不改值。电子件通常为 1.0，不触发。
- `diagnose_s4.py`：模板改用 `local_run.load_template`，同时接受旧版 `field_map`
  与 v2 箱体模板（按 `match_rule.header_fingerprint` / `tables[].columns` 转别名）。
- `algo/verdict.py`：内容层 `undetermined` 且 limitations 含「未解析到交易明细，
  无法核对」时，`verdict_reason` 直接写该句，不再落到首个 skipped 检查的细节。
- `algo/report.py`：触发的结论若仍在使用未校准默认值（NET_OUTFLOW 单月下限 /
  FAST_IN_OUT 金额下限 / NEW_LOAN 占比 / CRYPTO_HIT 金额下限，且配置等于默认值），
  limitations 注明「使用了未校准默认值，仅作线索」；银行改过值则不标注。
- `algo/samples.py`：`SAMPLE_SET_VERSION = 2`，新增两类伪造——
  - `content_row_deleted`：删一笔但保留原页脚，C1/C2/C3 同时暴露；
  - `content_page_splice`：两个时段拼页，页内各自闭合，接缝处余额链断（C1）。
  生成器同步写 manifest，仍不提交 PDF 与清单。
- 测试：`tests/test_report.py` 补低置信与未校准标注；`tests/test_samples.py`
  补删行、拼页断言；`tests/test_eval.py` 总数与 `sample_set_version` 改 8 / 2；
  `tests/test_verdict.py` 补 0 笔时的结论理由。
- 文档：`algo/README.md`、`chat.md`、`tasks.md` 同步样本 v2、低置信留痕、
  AL-44 算法侧完成状态、AL-28/29 验收阻塞说明。
