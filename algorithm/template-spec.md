# 模板与字段映射规范（field_map v1）

> 这是什么：模板标注的数据契约与校验规则 · 谁写：算法组 · 何时更新：模板结构变化时
> 上游依据：contract.md 的 template 表与接口；本文件细化 field_map 的内部结构。
> 为什么要单独写：原文档只写「字段与坐标映射」，算法无法消费、前端无法实现、两侧必然对不上。

# 一、边界

| 我们负责 | 我们不负责 |
| --- | --- |
| 模板结构、坐标基准、校验规则、命中规则 | 模板内容对不对（银行自己定） |
| 试解析结果的结构与错误码 | 用不用这个模板（银行决定启用哪个） |

# 二、坐标基准（写死，不许改）

统一用**相对比例**，原点在页面左上角，取值 0 到 1：

```text
x, y : 距页面左边/上边的比例
w, h : 占页面宽/高的比例
page_size.w/h : 标注时使用的基准页面尺寸（pt），仅作记录
```

为什么不用像素：缩放、DPI、打印尺寸一变，像素坐标全错。比例坐标与显示无关，同一模板可复用到任意渲染尺寸。

四条硬规则：

1. 任何坐标落在 `[0, 1]`；越界即视为无效标注。
2. `w` 与 `h` 必须大于 0；小于 0.002 视为误触。
3. 跨页的字段分开标注，每条带自己的 `page`。
4. 保存前统一四舍五入到 4 位小数，避免浮点噪声。

# 三、结构（v1）

```json
{
  "schema_version": 1,
  "bank_code": "ICBC",
  "page_size": { "w": 595.0, "h": 842.0 },
  "match_rule": {
    "bank_name_keywords": ["中国工商银行"],
    "header_fingerprint": ["交易日期", "摘要", "对方户名", "发生额", "余额"]
  },
  "meta_boxes": [
    { "id": "m1", "field": "account_no", "page": 1,
      "rect": { "x": 0.08, "y": 0.21, "w": 0.12, "h": 0.02 } },
    { "id": "m2", "field": "period", "page": 1,
      "rect": { "x": 0.55, "y": 0.21, "w": 0.20, "h": 0.02 } }
  ],
  "tables": [
    { "id": "t1", "page": 1,
      "area": { "x": 0.06, "y": 0.30, "w": 0.88, "h": 0.55 },
      "header_y": 0.31,
      "columns": [
        { "field": "txn_date",     "x": 0.06, "w": 0.12 },
        { "field": "summary",      "x": 0.18, "w": 0.30 },
        { "field": "counterparty", "x": 0.48, "w": 0.20 },
        { "field": "amount",       "x": 0.68, "w": 0.12 },
        { "field": "balance",      "x": 0.80, "w": 0.14 }
      ] }
  ],
  "custom_fields": [ { "code": "branch", "label": "开户网点" } ],
  "meta": { "created_at": "2026-10-29T12:00:00+08:00", "sample_name": "sample.pdf" }
}
```

字段含义：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| schema_version | 是 | 结构版本，变化时升版本，旧模板仍可读 |
| bank_code | 是 | 版式所属银行；同 bank_code 只允许一个启用版本 |
| page_size | 否 | 标注时的基准尺寸，用于换算出 pt 坐标与排查问题 |
| match_rule | 是 | 命中规则，见第六节 |
| meta_boxes | 否 | 单值字段框（账号、户名、期间、合计等） |
| tables | 否 | 明细表格区；没有它就只能拿单值，无法逐行抽取 |
| custom_fields | 否 | 银行自建字段，不污染核心字典 |
| meta | 否 | 标注信息，便于追溯 |

**meta_boxes 与 tables 至少要有一个**，否则模板没有意义。

# 四、核心字段字典

字段 `code` 固定，中文名可显示为不同说法，但 code 不许改。

| code | 中文名 | 类型 | 必填 | 所在位置 |
| --- | --- | --- | --- | --- |
| account_no | 账号 | string | 是 | meta |
| account_name | 户名 | string | 否 | meta |
| bank_name | 开户行 | string | 否 | meta |
| period | 交易期间 | string | 是 | meta |
| opening_balance | 期初余额 | money | 否 | meta |
| closing_balance | 期末余额 | money | 否 | meta |
| total_in | 收入合计 | money | 否 | meta |
| total_out | 支出合计 | money | 否 | meta |
| txn_date | 交易日期 | date | 是 | table |
| summary | 摘要 | string | 是 | table |
| counterparty | 对方户名 | string | 否 | table |
| direction | 借贷方向 | enum | 否 | table |
| amount | 发生额 | money | 是 | table |
| balance | 余额 | money | 是 | table |
| currency | 币种 | string | 否 | meta |
| remark | 备注 | string | 否 | table |
| branch | 开户网点 | string | 否 | meta |

必填集合（缺一即模板不可用）：`account_no`、`period`、`txn_date`、`summary`、`amount`、`balance`。

## 自定义字段的规矩

| 规则 | 说明 |
| --- | --- |
| code 格式 | `^[a-z][a-z0-9_]{1,30}$`，不许与核心字段重名 |
| 必须写中文名 | 否则报告里出现英文 code |
| 只在本模板内生效 | 不自动进入全局字典；需要全局化要走变更流程 |

# 五、表格区与列

| 概念 | 含义 | 为什么需要 |
| --- | --- | --- |
| area | 明细区域的外框 | 划定行扫描范围，排除页眉页脚 |
| header_y | 表头基线位置 | 用于识别表头行、跳过表头 |
| columns | 每列的水平区间 | 切列；不含列边界就无法把文本归到字段 |
| page | 表格所在页 | 跨页表格按页分别标 |

约束：

1. 列区间必须在 `area` 的横向范围内。
2. 列之间不允许重叠；相邻列允许 0 间隙。
3. 同一表格内列字段不许重复；跨表格允许（如续页）。
4. 行高不存：由表头基线到区域底部按行间距自适应，避免不同行距的版式失效。

# 六、命中规则（怎么知道该用哪个模板）

判定顺序，前一档命中即停止：

| 序 | 判据 | 命中条件 |
| --- | --- | --- |
| 1 | 银行名 | 页面文本包含 `bank_name_keywords` 任一词 |
| 2 | 表头指纹 | `header_fingerprint` 中至少 80% 的标签在页面上按序出现 |
| 3 | 兜底 | 都不命中 → 通用解析，并在报告 `limitations` 写「未命中模板」 |

同 `bank_code` 多个启用版本时视为配置错误，按**最新启用版本**执行并告警。

# 七、校验规则（这就是「错误解析提醒」的判据）

标注完成后、保存之前必须过一遍。**错误阻止保存，警告只提示。**

## 错误（必须改）

| 码 | 检查 | 提示语 |
| --- | --- | --- |
| T001 | 未填 bank_code | 请先选择版式所属银行 |
| T002 | 既无字段框也无表格区 | 至少标注一个字段框或一个表格区 |
| T003 | 缺必填字段 | 缺少必填字段：账号、交易期间… |
| T004 | 表格区没有列 | 表格区需要至少一列，否则无法切分明细 |
| T005 | 同一字段被多处标注 | 字段「发生额」被标注了 2 次，请保留一处 |
| T006 | 坐标越界或尺寸为 0 | 有框超出页面范围或尺寸过小 |
| T007 | 自定义字段 code 非法或重名 | 字段编码只能用小写字母、数字、下划线，且不能与内置字段重名 |
| T008 | 列区间超出表格区 | 列左边界超发明细区域 |
| T009 | 表头指纹为空 | 请至少填写一个表头关键词，否则无法自动命中 |

## 警告（可以保存，但要知道）

| 码 | 检查 | 提示语 |
| --- | --- | --- |
| W001 | 字段框落在表格区内 | 该框在明细区域内，可能是重复标注 |
| W002 | 列有重叠 | 列「摘要」与「对方户名」有重叠，抽取可能串列 |
| W003 | 未标 table | 没有表格区，只能取到账户信息，无法解析明细 |
| W004 | 页面尺寸缺失 | 未记录基准页面尺寸，排查问题时不便 |
| W005 | 只有一页但表格可能跨页 | 建议标注续页表格 |

# 八、试解析（dry-run）

标完必须能立刻验一遍，否则录错了没人知道。

> 现状：dry-run 接口未实现，银行侧页面先用 `frontend-admin/src/mocks/ocr_lines.json` 演示「解析结果回贴原页 + 低置信标红」。真实结果接入后替换该 mock。

| 项 | 约定 |
| --- | --- |
| 接口 | `POST /api/v1/templates/dry-run`（建议，需 PM/PD 落进 contract） |
| 输入 | 样本文件 + field_map |
| 输出 | 抽到的字段值、明细条数、自检三项（完整率/平均置信度/低置信行占比）、命中的错误码 |
| 失败 | 返回 T1xx 结构错误或 X1xx 抽取错误，不返回半个结果 |

抽取侧错误码：

| 码 | 含义 | 提示 |
| --- | --- | --- |
| X101 | 表头未识别 | 表头基线附近找不到列名，请调整表头高度 |
| X102 | 明细 0 行 | 区域划到了空白处，或行距判断失败 |
| X103 | 金额解析失败占比过高 | 列可能错位，检查发生额/余额列 |
| X104 | 字段取值超出页面 | 标注坐标与服务端渲染尺寸不一致 |

# 九、可扩展性

| 扩展需求 | 做法 | 不需要改什么 |
| --- | --- | --- |
| 新增核心字段 | 加进第四节字典 + 升 schema_version | 不必改标注逻辑 |
| 多页表格 | `tables` 加一条，`page` 不同 | 结构已支持 |
| 一个字段多处出现 | 同一 field 允许多个 box（如账号出现在页眉与页脚）→ 取第一个非空 | 结构已支持，需在抽取侧去重 |
| 新银行 | 新建 bank_code 模板 | 不动已有模板 |
| 字段类型增加（如枚举） | 字典的 type 扩展 | 前端按 type 渲染不同输入 |

# 十、合规（样本原件的处理）

标注用的样本是**客户真实流水**，模板库会变成第二份客户数据仓库。

| 要求 | 做法 |
| --- | --- |
| 脱敏 | 入库前把账号、姓名、证件、手机号替换为等长假值，保持版式不变 |
| 权限 | 只有模板管理员可看样本；导出需留痕 |
| 留存 | 与业务数据同期限（三年），到期归档 |
| 禁止 | 样本不得进 Git、不得出现在公开仓库的任何位置 |

## 标注外推（v2）

| 输入 | 输出 |
| --- | --- |
| 1-3 个标注（字段 + 页码 + 坐标） | field_map（字段→表头文字）+ 每字段来源与置信度；反验不过时 `valid=false`、无 field_map |

外推步骤：锚点定位 → 横向聚类出列 → 表头行定位取别名 → 未标列按统计特征推断 → 反验 → 输出 warnings。

反验（AL-36）：用推断出的模板对同一文件真解析一遍，任一条件不满足即拒绝产出模板，只返回 warnings：

| 条件 | 判据 |
| --- | --- |
| 必需字段齐全 | `txn_date` / `amount` / `balance` 都能推断出 |
| 能解析出明细 | 解析笔数 > 0 |
| 行数守恒 | 有页脚声明时，解析笔数与声明一致 |
| 金额/方向可取 | 过半笔数取不到金额或收/支方向 → 列映射可疑 |
| 余额链闭合 | 可核对 ≥2 处且全部不符，或 ≥5 处且不符超过 20% → 金额/余额列可能颠倒 |

实测：工行 8 页加密件，只标 交易日期/收入支出金额/余额 三处，解析 191 笔且金额、余额、摘要与完整模板一致。把金额与余额两处标注对调，反验报「余额链全部不符」并拒绝出模板。
