# 标注画布：让框看得懂，也让框对得准

> 2026-11-14 · 分支 `rebuild/v1`
> 触发：使用者反馈「完全不理解你画的框是什么」「务必确保视觉上和真实识别中都是对齐的」。

## 一、为什么之前看不懂

四个原因叠在一起，缺一个都不会这么糟：

| 原因 | 表现 |
| --- | --- |
| pdf.js 缺 cMap，中文 CID 字体画不出来 | 画布一片白，只剩框 → 框看起来像凭空乱画 |
| 没有图例 | 蓝框、紫框、红格各是什么，全靠猜 |
| 列带从表头 y 起画 | 列名被圈进第一个格子里，像「系统把标题当数据」|
| 表头行判定用页面前 40% 的行数 | 短页面（样例 8 行）把真表头切掉了，整列错位一格 |

## 二、改了什么

1. **把 cmaps 与 standard_fonts 一起打包**（`web/public/cmaps`、`standard_fonts`，来自 pdfjs-dist），
   `getDocument` 传 `cMapUrl/cMapPacked/standardFontDataUrl`。现在中文件能正常渲染出字。
2. **加图例**：蓝框＝一列（每行都有），框里的小格是这一列读到的每个值；紫框＝整份只有一个的信息
   （卡号、户名这类）；并明确写「框的位置就是系统实际取值的位置，可以拖动校正」。
3. **表头行按关键词命中判定**（前 30 行里能被认成表头词的 token 最多的那一行），不再用坐标猜，
   也不再受「页面行数 × 40%」限制。
4. **列带只圈住真实数据**：从第一个被读到的格子起、到最后一行止；格子相对框顶定位，不再减表头 y。
5. **口令栏用完即收**：口令正确解析成功后就隐藏；本来就是明文件的根本不会出现这一栏。

## 三、对齐的证据（放大 2 倍逐块看）

以 `clean/icbc_card.pdf` 为例：

- 紫框 1：正好圈住`卡号：6 2 2 2 0 2 0 2 0 0 0 0 1 2 3 4`；
- 紫框 2：正好圈住`户名：张 三`；
- 紫框 3：正好圈住`开户行：中国工商银行北京分行`；
- 蓝框「交易日期」从 `2026-01-05` 起到 `2026-01-07` 止，三个红格分别压在三个日期上，**表头不再进框**；
- 「摘要 / 对方户名 / 借贷标志 / 交易金额 / 余额」同理。

接口侧同一份文件：6 条列带的 cells 首项都是数据（`2026-01-05`、`工资`、`某公司`、`贷`、`12,500.00`、`13,200.00`），
没有表头混入；单值 4 条取值正确。

## 五、还没做的

1. **单值框不能拖**：位置靠标签自动定位；列可以拖、单值不能，能力不一致。
2. **列带宽度按读到的值包络，不按表头宽度**：表头比数据短时，蓝框会显得偏右（这是对的，框住的是值）。
3. **没做「只显示某一列」的聚焦模式**：列多时框会互相挨着，看图仍需要放大。
