# 智能风控 · 信贷项目 第二批修复说明（B3–B6 + F1–F6）

本次修复覆盖第二批「前后端 P0 止血」全部 **10 项问题**（后端 4 项 + 前端 6 项），共修改 **16 个源码文件**。所有文件保持原仓库相对路径，可直接覆盖至项目根目录使用（注：`backend/routers/tasks.py` 与 `backend/services/task_runner.py` 已包含第一批的 `T6` 修复，直接覆盖即可，无需手动合并）。

## 一、后端修复明细（B3–B6）

### B3｜修复慢通道调度器报告数超 50 卡死 `pending` 与空闲窗口失真
- **修改文件**：`backend/services/worker.py`、`backend/services/verify_scheduler.py`
- **修复内容**：
  1. `worker.py` 新增 `_LAST_FINISHED_AT` 与 `last_finished_at()`，在进程池回调和 inline 结束时准确记录快通道最后完成时间。
  2. `verify_scheduler.py` 的 `_pick_one()` 改为优先使用数据库 `JSON_EXTRACT(verification, '$.status') = 'pending'` 过滤，非 MySQL 方言回退游标分页扫描（`Report.id > last_id`），彻底消除历史报告超过 50 条后新报告永久卡死 `pending` 的缺陷；同时允许 `image` 载体纳入慢通道复核；`_loop()` 结合 `worker.last_finished_at()` 精确判定 5 秒空闲窗口。

### B4｜打通补件接口投递后台执行与补件材料读取
- **修改文件**：`backend/services/workflow.py`、`backend/routers/tasks.py`、`backend/services/task_runner.py`
- **修复内容**：
  1. `workflow.py` 允许 `NEED_SUPPLEMENT -> QUEUED` 状态迁移。
  2. `tasks.py` 的 `add_supplement` 改为流转至 `QUEUED` 后调用 `worker.submit_task(task.id)` 真正触发后台重跑。
  3. `task_runner.py` 按 `TaskFile.seq` 顺序读取该任务全部材料（含补件），多份 PDF 自动合并页流后统一解析分析，并在 `check_result` 记录 `material_count`。

### B5｜修复 OCR 路由凭据校验并接入主分析链路
- **修改文件**：`backend/services/ocr_api.py`、`backend/routers/ocr_routing.py`、`backend/services/task_runner.py`、`backend/services/analysis.py`
- **修复内容**：
  1. `ocr_api.available(db=None, extra_key=None)` 补齐对页面新提交 `api_key` 与数据库已存 `OcrRouting.api_key` 的检测，解决管理员在界面填 Key 开启路由时必报 `400 E_NO_CREDENTIAL` 的问题。
  2. `routers/ocr_routing.py` 在读写接口传入 `db` 与 `extra_key`。
  3. `task_runner.py` 接入 `ocr_routing.should_use_api(session, img_count)` 并透传给 `analysis.py`，将引擎路由决策（`local` / `cloud_api`、`workers`、`model`）落入 `check_result.ocr_route`。

### B6｜消除两处运行期崩溃隐患（`NameError` 与影像件 `IndexError`）
- **修改文件**：`backend/main.py`、`algorithm/algo/self_check.py`
- **修复内容**：
  1. `backend/main.py` 补齐 `HTTPException` 导入。
  2. `algorithm/algo/self_check.py` 的 `_page_text` 对非 `%PDF` 影像件直接返回空列表（不再抛 `FileDataError`），`run_self_check` 在无文本层或 `plumber_pages` 为空时将 `S1–S4` 安全降级为 `limited`，彻底消除 `plumber_pages[-1]` 越界崩溃。

## 二、新版前端 `web/` 修复明细（F1–F6）

### F1｜修复登录 401 误报「已过期/令牌无效」与后端中文报错被吞
- **修改文件**：`web/src/api/client.ts`、`web/src/api/errors.ts`
- **修复内容**：
  1. `client.ts` 改为先解析响应 JSON 并兼容字符串/对象两种 FastAPI `detail`；`/auth/login` 的 401 不清空会话且透出后端原文（如「用户名或密码不正确」）。
  2. `errors.ts` 补齐 `E_FORBIDDEN`、`E_EXISTS`、`E_NOT_FOUND`、`E_SELF`、`E_LAST_ADMIN`、`E_PARAM`、`E_NO_CREDENTIAL`、`E_FEATURE`、`E_EXPR`、`E_OP` 等错误码，并在未知码或明细校验错误时优先显示后端中文提示而非覆盖为「操作失败」。

### F2｜对齐报告页慢通道复核状态与差异明细展示
- **修改文件**：`web/src/pages/banker/ReportPage.tsx`
- **修复内容**：新增 `verifyStatusMeta` 对齐后端 `passed / discrepancy / failed / pending` 四态，展示 `checked_at`、`txn_count_fast`、`txn_count_slow`、`diff_count`、`reason` 以及可展开的 `diffs` 差异明细列表。

### F3｜拆清报告页顶栏「真实性得分」与「综合评分」
- **修改文件**：`web/src/pages/banker/ReportPage.tsx`
- **修复内容**：顶栏拆分为独立的「真实性得分（`trust.score` / `trust.label`）」与「综合评分（`scores.overall` / `scores.grade_label`）」两张卡片，不再张冠李戴。

### F4｜报告页原件抽屉接入加密件口令补输与坐标单位自适应
- **修改文件**：`web/src/pages/banker/ReportPage.tsx`
- **修复内容**：向 `PdfPageCanvas` 透传 `password`、`onPasswordRequired`、`onError`，遇加密 PDF 弹出页内口令输入框解锁；新增 `isNormalizedCoord` 自适应区分 `0~1` 相对坐标与 `pt` 绝对坐标，防止证据图钉钉死在左上角。

### F5｜修复 `EntitiesPage` 合并响应契约、字符串崩溃隐患与重复全量请求
- **修改文件**：`web/src/pages/banker/EntitiesPage.tsx`
- **修复内容**：新增 `normalizeMergeResult` 统一兼容 `GET /entities/merge`（嵌套）与 `POST /tasks/merge`（平铺）两种响应；新增 `formatMetricValue` 防止字符串 Decimal 触发 `.toFixed(2)` 白屏；主体读取优先使用 `holder_masked`；将 `load` 依赖改为 `[]` 消除切换下拉框触发重复请求。

### F6｜移除过时 `ComingSoon` 占位页并补齐规范路由别名与旧 Hash 书签兼容
- **修改文件**：`web/src/pages/banker/BankerApp.tsx`、`web/src/App.tsx`
- **修复内容**：移除指向不存在 `/bank-old/` 的 `ComingSoon`，补齐 `dashboard`、`ocr-routing`、`metric-defs`、`verification-defs`、`import`、`import-template`、`annotate/*` 路由别名与标准 404 引导；在 `App.tsx` 新增 `LegacyHashRedirect` 自动兼容 `/app/#/...` 与 `/bank/#/...` 旧书签。
