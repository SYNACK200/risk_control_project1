# 模板字段智能分析专项包 归并记录

> 2026-11-21 · 分支 `rebuild/v1` · 来源：`模板字段智能分析专项修复包.zip`

## 一、这一包带来了什么

一个「在模板库页面直接建模板」的入口，不再要求先去画布上手工拖框：

- `backend/services/template_analyzer.py`（新）：**短字段就近匹配**（卡号/户名/起止日期/开户行/币种，
  页眉锚点 → 同行粘连 / 右侧就近 / 正下方三级提取，带 1-编辑距离容错）+ **标题字段版式分析**
  （表头行评分、按整行表头词切列边界、数据行投影到页脚截断、产出 field_map + layout + meta_boxes）
- `POST /api/v1/templates/analyze-fields`（新）：上传样例 PDF + 两类字段配置 → 预览结果，可选直接入库/启用
- `TemplatesPage.tsx`：面板化交互（字段表可编辑、分析结果与试解析预览、一键保存草稿/启用、跳画布微调）
  另带「载入内置标准模板」按钮与各栏计数
- `backend/tests/test_template_field_analyzer.py`（新）：建行/广发/工行样例回归

## 二、归并时发现并修掉的两处问题

1. **`POST /templates/import` 被改坏了**（回归）
   包里的 `templates.py` 把签名写成 `payload: dict | list`，FastAPI 会把裸 `dict|list` 当成**内嵌字段**
   `payload`，于是标准导出 JSON 直接 422 `Field required`。实测 `/templates/39/export` → 原样
   `import` 得到 422；已在签名上显式加 `Body(...)`，复测 200。
   这条不修就会把「导出→导入」整条迁移路径打断，而它是模板备份/搬运的唯一手段。
2. **空状态引导被覆盖**（本地改动丢失）
   包里的 `TemplatesPage.tsx` 基线没有上一轮加的「这一栏没有模板，但库里有 N 份在用/草稿/已停用/回收站」
   引导块，已按原样补回（它自带的 `counts` 保留，只去掉我重复声明的那份）。
   另把 `banker.ts` 的 `TemplateLayout.page_size` 类型补回——第 4 批之后这是第三次被覆盖，`tsc` 会报 TS2339。

## 四、遗留

1. 这份真件没有「收入金额/支出金额」两列（只有一列交易金额 + 借贷标志），所以分析器报 `amount_in/amount_out`
   未匹配；解析仍能出金额与方向（走解析器的金额单列处理）。要不要在分析器里支持「单列金额 + 借贷标志」
   直接生成 amount_in/out，是产品决策，等你定。
2. 同一真件的 `summary` 仍为空：页面上「摘要」一列本身没值，值在「交易地点/附言」里；这属于字段语义
   取舍（摘要取哪个列），也需要你定。
3. `T8`（点表头定列）与 `F9`（实体页大改版）依旧未做。
