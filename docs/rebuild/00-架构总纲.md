# 重构总纲（rebuild/v1）

> 一句话：把「一个进程里的五个大文件」换成「一个能力注册表 + 一堆可拆卸插件」，
> 同时把解析从「死模板」换成「可外推的锚点扩散」，把指标从「40 项写死」扩展成「特征衍生框架」。
> 旧版本已封存为 `archive/v0.40.0` / `v0.40.0-sealed`，是本次重构的行为对照物。

## 1. 不做什么

| 不做 | 原因 |
| --- | --- |
| 不重写核验口径 | C1–C10、四层权重、一票否决的成因区分是业务资产，有测试守着，只搬家不改判据 |
| 不引入外部大模型处理真实流水 | 红线：真实客户流水不出内网。模型兜底默认关闭，开启需显式配置且先脱敏 |
| 不一次性推倒 | 每阶段测试全绿、服务能起、可回滚；旧目录在 M6 前不删 |
| 不建第二个并行库表体系 | `data/` 的 schema 权威、脱敏、留存并进新数据层；其余冻结在封存版本里 |

## 2. 四条拍板（2026-11-10）

| # | 决定 | 工程含义 |
| --- | --- | --- |
| Q1 | 纵向业务切片 + 能力注册表 | 每个能力一个目录，实现统一契约，启动扫描注册；主干不认识实现，router 只校验与调度。**解耦是目的，注册表只是手段** |
| Q2 | 特征衍生双轨 | 算法侧注册算子（Python 插件），银行侧用表达式/步骤编排；算子能力覆盖逻辑、比较、时间窗、分组聚合，不再只有加减乘除 |
| Q3 | 死模板靠外推，多方案综合 | 关键词锚点 + 扩散生长框 + 列带推断 + OCR；几何/投影聚类做无模板兜底；版式分析库（本地）做第三道；外部 API 默认关闭 |
| Q4 | 零新依赖的并发 | DB 队列 + 进程池 + 心跳/重试/退避/取消；银行侧队列可查；目标 50 并发上传 |

## 4. 能力契约

一个能力就是一个类，声明四件事：**我叫什么、我吃什么、我产什么、我怎么跑**。

```python
@capability
class AnchorLayout:
    name = "layout.anchor_spread"      # 稳定 id，配置与审计都用它
    version = "1.0"
    requires = ("document",)           # 依赖的契约名
    provides = "layout"                # 产出的契约名
    def run(self, ctx, inputs) -> LayoutPlan: ...
    def describe(self) -> dict: ...    # 供队列/管理界面展示
```

四条硬规则：

1. **主干不 import 任何具体能力**。`pipeline` 只认识契约类型名与注册表。
2. **能力之间只通过 `core/contracts.py` 交换数据**，不互相 import。
3. **能力可关**。配置里把某个能力置灰，pipeline 自动降级（比如没有 `layout` 就走通用解析），并在报告 limitations 里说明降级原因。
4. **同名能力可并存多实现**，由配置选择（例如 `parse.template` 与 `parse.generic`），便于 A/B 与回滚。

错误策略：`fail`（默认，任务置 FAILED 并留审计）与 `degrade`（能力失败时产出「不可用」结果并继续，
报告里标注核验受限）。**核验层永远用 degrade**——不可算 ≠ 通过，这是老版本的既有口径。

## 5. 新解析框架（M2）

死模板的根因：模板是**前提**，匹配不上就没有第二套几何。新框架把模板降级为**加速层**，
主干是「不依赖模板也能定位表格」的三段式：

### 5.1 锚点扩散（用户提出的主路线）

1. 给出一份**跨行不一致的关键词表**（交易日期/摘要/发生额/余额/借/贷/对方户名…，每家银行叫法不同）。
2. 在页面上定位每个关键词的首次出现——它是**种子**，不是判据。
3. 从种子向下**扩散生长**：同一列带上继续找同形态的词（日期 → 日期形、金额 → 金额形），
   逐步把「一个词」长成「一条列带」，再右向扩散找同行的兄弟列带。
4. 列带收敛后得到表格框（左边界 = 最左列带起点，右边界 = 最右列带终点，上下边界由连续性判定）。
5. 按框裁切后交给 OCR/文本层读取，行切分用「日期列的 y 变化」当行锚。

为什么这条路能外推：它不要求知道版式，只要求**至少一个关键词出现**；
关键词在不同行出现不同叫法也能各自长成独立列带，最后按语义合并。

### 5.2 几何聚类兜底

没有可用关键词时，退回纯几何：文字块按 y 聚类成行、按 x 间隔切列、连续行段判定为表格区。
这条路对「表头坏了但数据规整」的件有效。

### 5.3 版式模型兜底（默认关闭）

本地优先（PaddleOCR PP-StructureV3 / 版面分析包）；外部 API 仅在显式开启且文件已脱敏时可用。
开启后仍要过 5.1/5.2 的交叉校验，任何单一路线的结果不单独采信。

### 5.4 置信与升级

每级产出带 `layout_confidence`（列带稳定度、行锚一致性、金额/日期缺失率）。
低于阈值才升级到下一级；升级原因写进报告，让银行知道这份是怎么读出来的。

### 5.5 模板的新位置

模板 = 已收敛的 layout 快照 + 优先级。命中模板直接跳过 5.1（快），
但**必须**跑一次轻量校验（覆盖率、金额缺失率、余额链断裂率），偏差过大就回落到 5.1 并提示「临时标注/重采模板」。

## 6. 特征衍生框架（M3）

目标：既要有足够多的内置衍生特征，又要让银行自己配。老版本的「元算子」只有加减乘除，本次扩到四层能力。

### 6.1 算子协议

```python
@operator
class SumByGroup:
    code = "sum_by_group"
    inputs = {"value": "number", "by": "string"}
    output = "table"           # number / bool / table / series
    def apply(self, frame, **kwargs): ...
```

算子分四族：

| 族 | 例 | 老版本有没有 |
| --- | --- | --- |
| 数值 | sum/mean/median/std/max/min/pct_change/cv | 部分 |
| 逻辑与比较 | gt/ge/lt/le/eq/and/or/not/if_else | 无 |
| 分组聚合 | sum_by/mean_by/count_by/rank_by/distinct_count | 无 |
| 时间窗 | within_days/between_dates/monthly/rolling/dow/hour_band | 无 |

### 6.2 表达式与步骤双形态

- **步骤形态**（银行可拖拽）：`[{atom, args}, …]` 顺序执行，与老 `CustomMetric.steps` 兼容。
- **表达式形态**（银行可写）：`sum(amount where direction=='out' and hour(date)>=22) / sum(amount)`，
  解析成 AST 再落到同一套算子执行——两种形态共享一套语义，避免两套口径。

### 6.3 特征库

特征定义（代码 + 参数 + 版本）与特征值分表存：定义只增不改，值按 `(task_id, feature_code, version)` 存。
产物同时供指标、报告、模型导出三处消费，天然带 `caliber_version`。

### 6.4 泛化验证

每个特征必须能回答三问：跨银行能不能算（同一码在 4 家版式上）、缺列时怎么说（null + 原因，不填 0）、
口径变了怎么追溯（版本号）。做不到就不进特征库。

## 7. 队列与并发（M5）

| 项 | 做法 |
| --- | --- |
| 队列 | `job` 表：状态、优先级、入队/开始/结束时间、心跳、尝试次数、失败原因、所在阶段 |
| 可见化 | 银行侧「队列」页：排队第几位、卡在哪个阶段、预计等待、失败原因、重试/取消按钮 |
| 并发 | 进程池（CPU 密集：解析/OCR）× 线程池（IO：DB/HTTP），上传受理不等解析，立即返回 JOB id |
| 重试 | 指数退避，可重试错误与不可重试错误分开；超次数进 `dead` 列人工处理 |
| 慢通道 | 只在队列空闲阈值以下启动，抢占时让路（老版本的 `_fast_busy` 教训：判据要读真实计数） |
| 目标 | 50 并发上传不丢任务；单任务进度可查 |

## 8. 前端合并（M6）

单 SPA：`/app/*` 借款侧、`/bank/*` 银行侧、`/` `/login` `/register` 公开页。
共用一套 `api`、`auth`、`errors`、`ui` 组件；按角色路由懒加载分包，避免借款侧下载银行侧代码。
现有 1046 行的标注页拆成「画布 / 工具条 / 步骤导航 / 列字段列表 / 试解析预览」五个独立组件。

## 10. 风险登记

风险：新解析框架在真实劣质件上没有对照样本，M2 的「比旧版多解析出笔数」可能无从验证。
对策：先把 `流水文件/` 里的样例与合成样本做成固定夹具，同时准备人工标注的期望笔数；没有对照就不宣布达标。

风险：能力注册表容易变成「另一种形式的全局单例」，写久了又耦合回去。
对策：主干只允许 import `core`；加一条测试扫描 `api/` 与 `core/` 的 import，出现具体能力包即失败。

风险：特征表达式一旦允许自由编写，口径会失控（同一个名字两种算法）。
对策：表达式只能调用注册算子，且每个特征定义落库时记 `operator_version`，报告按版本解释。

风险：M5 的 50 并发目标在本地单机脚本上测不出来。
对策：用任务注入脚本压队列（不压 OCR），量的是「受理不丢、状态可查、失败可重试」，不是端到端时延。
