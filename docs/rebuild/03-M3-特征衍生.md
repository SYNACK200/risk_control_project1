### 3. 表达式与步骤等价

同一语义两种写法，落同一个执行核，测试里逐值比对
（`tests/test_equiv.py`：`steps` 与 `expr` 在 5 组特征上结果相同）。

### 4. 例子：表达式 -> 结果

| 表达式 | 结果 |
| --- | --- |
| `sum(amount, where=direction=='out')` | 3450.50 |
| `count(where=trade_time is not none)` | 若原件没印时分秒则为 0 |
| `sum(amount, where=(direction=='out') and (hour>=22 or hour<6))` | 缺 trade_time 时为 none |
| `if_else(sum(amount, where=direction=='in') == 0, none, sum(amount, where=direction=='out') / sum(amount, where=direction=='in'))` | 0.13802 |
| `1 + 2 * 3` | 7（优先级） |
| `none and false` | false（三值逻辑） |

## 与老版本的关系

老版本 `CustomMetric.steps` 的写法仍可直接跑（`filter_direction` / `sum` 等 12 个算子标了 `compat=True`）。
新增的是它做不到的那部分：逻辑比较、三值、条件选择、分组聚合、时间窗。这正是甲方说的
「原先只支持最简单的加减乘除，对逻辑结构与复杂运算不支持」。
