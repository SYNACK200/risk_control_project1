# M6 第 5 步：标注页（第一版：预读驱动的自动标注）

> 日期 2026-11-10 · 分支 `rebuild/v1`

## 交付

| 项 | 内容 |
| --- | --- |
| 页面 | `/bank/annotate` |
| 流程 | 选样本 → `POST /templates/probe` 预读 → 自动生成列带 → 人工微调字段/x/w 与表格区 → 保存为草稿模板 |
| 保存 | 先 `POST /templates` 建草稿，再 `PUT /templates/{id}` 写 `layout` + `field_map`，跳转模板详情 |
| layout 格式 | `{page_size, page_count, tables:[{page:0, slot, area, headerY, columns:[{field, fields, x, w}]}]}`，与 M2 解析器、旧后端一致 |

## 为什么先做这条路

旧标注页 1046 行，是封存版失败过 5 次以上的地方（多行 JSX 改动破坏结构、事件拦截误伤选中）。
硬搬一个画布编辑器而不带回归证据，风险远大于收益。

而预读接口已经能给出**建议标注**（表头词位置、表格区、表头 y），多数模板调几个数值就够用。
所以第一版先做「自动标注 + 数值微调」，把手绘框留成独立下一步。

## 缺口（明确的下一步）

问题：手绘交互没迁——拖表格区、画新列、八个手柄改大小、缩放拉条、选中/拖动/画新对象四种模式的互不干扰。解决状态：未做，页面已标注「需要时先用 /bank-old/」。事后反馈：这是整个 M6 里唯一「功能明显少于旧版」的一页；它也是唯一必须带浏览器交互验收的页面（构建通过完全不能证明它好用），所以下一轮会单独做、单独验收，不和别的页面混在一起。

问题：预读对没有银行名的样本返回 `bank_code=null`（合成样本即如此），保存前必须手填银行代码。解决状态：已按「必填」处理并在界面上拦截。事后反馈：真实银行流水通常印行名，这条只影响造出来的合成件；若真实件也有认不出的，那说明银行识别规则要补。

问题：这一版没有样本图和框回看，只有数值。解决状态：部分（模板详情页有版式回看，但没有图）。事后反馈：没有图时，调 x/w 是盲调；要真正好用必须把 pdf.js 渲染接进来——这就是手绘版要一起做的事。
