# 模板功能补齐（对应「补齐模板相关功能，注意我现在的业务」）

> 2026-11-14 · 分支 `rebuild/v1`
> 业务前提：模板是**加速层**——同一家银行同类版式的流水走快通道，不命中还有版式分析兜底。
> 用模板的人是银行侧管理员：他们标一次、试跑一次、启用，之后每份文件都靠它。

## 本轮补的四件事

### 1. 试跑（模板详情页）

以前模板存完就只剩「启用 / 停用」，能不能用要等一份真任务跑完才知道。
现在模板详情页有「试跑（不落库）」：选一份该银行的文件，直接返回

- 读出多少笔、几页；
- 逐页笔数与页眉是否识别（哪一页开始不好用，一眼看得出）；
- 前 12 笔明细；
- **缺了哪些必需列**。

底层用的是已有的 `POST /templates/{id}/preview`，这次补了缺列诊断与逐页口径修正。

顺带修了一个自相矛盾的显示：交易的 `page_no` 是 1 起，逐页统计却按 0 起遍历，
于是出现「总笔数 6、每页 0 笔」。现在统一 1 起。

### 2. 必需列（required_fields）

模板新增 `required_fields` 列（JSON，幂等迁移补列），详情页用 chip 勾选，保存即出新版本。

判据**按语义而不是按字段名一对一**（`services/template_checks.py`，试跑与报告共用一份）：

| 必需列 | 谁满足它 |
| --- | --- |
| `amount` | `amount` 或 `amount_in` + `amount_out` |
| `direction` | `direction` 或 `amount_in`/`amount_out` |
| `txn_date` | `txn_date` 或 `trade_time` |

不这么写就会误报：建行版式把金额拆成两列，按字段名一对一判会凭空报「模板缺列 amount」。

缺列时写进报告的第一条限制说明：**「模板缺列：account_no（这份版式模板未标注这些列，相关指标因此不可算）」**。
以前用户只看到一堆「不可算」指标，不知道是版式没标全，还是文件本身没有。

### 3. 同一页的多块表格区

`algorithm/ocr/parse.py` 原来每页只取**一个**表格框，同页的明细表 + 汇总表只能读到一块。
现在 `_layout_areas_for` 返回该页所有框，裁剪时「落在任意一块内即保留」。
单框模板行为完全不变（列表长度 1），所以新旧模板都安全。

### 4. 修一个会让「保存必需列」看起来没生效的坑

改必需列 = 出新版本（旧版本保留）。原来保存后页面仍停留在旧 id，读回的是旧值，看着像没保存。
现在保存后跳到新版本 id 并提示「已保存为模板 #x（vN 草稿）」。

## 还没做（明确）

1. **新平台（`rc_platform`）还没从数据库取模板**：`parse` 能力支持 `parse.template` 注入，
   但没人把启用模板喂进去；线上仍走老链路 `backend/services/analysis.py`。切换前必须补这层桥。
2. **标注画布还只能画一块表格区**：同页多块的**解析**已经支持，但界面上没有「加第二块」的入口，
   只有手写/导入的 layout 能用上这个能力。
3. **试跑没有历史记录**：每次试跑都是即时结果，不落库，也不统计「这个模板试跑过几次、失败几次」。
4. **模板导入 / 样本回看图（layout.png）** 仍只在旧版 `/bank-old/` 里。
