# 标注与模板：把门槛拆掉

> 2026-11-14 · 分支 `rebuild/v1`
> 触发：使用者反馈「完全不理解模板标注相关的逻辑」。

## 之前的门槛在哪

| 之前要使用者做的事 | 为什么是门槛 |
| --- | --- |
| 看懂「列带」「归一化 x/w」「layout」「field_map」 | 内部实现词，跟银行业务无关 |
| 从 11 个英文代号里选字段（txn_date / amount_in / counterparty_name） | 要用的人认中文不认代号 |
| 判断这是草稿还是在用，再去另一个页面点启用 | 保存完就该能用，不该多一步 |
| 先勾「必需列」才知道解析缺什么 | 顺序反了：人只想知道「读到了没有」 |
| 自己在空白画布上画框 | 多数情况系统已经认出来了，画框是例外而不是起点 |
| 加密件要自己想到去填口令 | 应该由系统在需要时开口问 |

## 现在的流程（三步，全中文）

**① 打开一份流水** —— 一个按钮「选择 PDF 文件」；也支持用已受理任务的原件、或内置样例。
遇到加密件会自动弹出「这份 PDF 的打开口令」。

**② 确认系统认出的列** —— 原件铺在左边，认出来的列直接框在上面并标中文名；
右栏每列一行：**中文名 + 它读到的前三个值**（如「交易日期 · 2026-01-05 · 2026-01-06 · 2026-01-07」）。
认错就点开改成中文名，偏了就在原件上拖这一列或拖两侧竖线。少一列就输入表头上的字（如「卡号」）补一列。

**③ 保存并启用** —— 一个按钮。选「这是哪家银行」之后保存，管理员保存即启用，
提示「以后建设银行的同类流水会自动用这份模板解析」。没有管理员权限时明确说「会先存成草稿」。

界面上不再出现任何英文代号：`counterparty`、`date`、`time` 这类系统内部别名也一并翻成「对方户名 / 交易日期 / 交易时间」。

## 模板详情页的定位调整

试跑与必需列仍在，但都标了「可选」——它们是**管理员排障用的**，不是使用者的必经步骤：
试跑回答「这份模板还准不准」，必需列回答「缺列时报告怎么措辞」。
字段映射表只显示中文，英文代号收进 tooltip。

## 验证

| 项 | 结果 |
| --- | --- |
| 第一步（未选文件） | 只有一个大按钮 + 两个「或者」下拉，页面无其他术语 |
| 第二步（载入 CCB 样例） | 「系统认出 6 列」，右栏六行全中文：交易日期/摘要/对方户名/收入金额/支出金额/余额，每行带读到的值 |
| 第三步（保存） | 选「建设银行」→「保存并启用」→ 跳转模板 #32 CCB v9，状态「在用」，6 列已标 |
| 构建 | `tsc -b` 0 错误，构建通过 |

## 还没做的

1. **画第二块表格区**：解析已支持同页多块，界面还没有入口（一页「明细 + 汇总」的件仍只认第一块）。
2. **试跑仍是可选动作**：保存后没有自动试跑一遍，也就不会当场提示「这份模板读出来 0 笔」。下一步应该保存时顺手试跑，把结果直接写在成功提示里。
3. **标注过程不可撤销**：拖偏了只能再拖回来，没有「撤销」。
