# 比较能力地图：现在能按什么筛，不能按什么筛

> 日期 2026-11-11 · 分支 `rebuild/v1` · 对应问题「晚上 18 点后的数据」「3σ 外的数据」

## 一句话

**时间维与分布维现在都能做，但要写成算子调用而不是 SQL 式的 WHERE。**
写不出「WHERE 语句」，是因为表达式是面向「一段流水」而不是面向「一张表」。

## 四层比较，逐个说

### 1 行级 · 时间维（能做）

| 想要 | 写法 | 说明 |
| --- | --- | --- |
| 18:00 之后 | `count(where=in_hours('18:00','23:59'))` | 含两端 |
| 22:00–次日 06:00 | `in_hours('22:00','05:59')` | 自动识别跨零点 |
| 周末 | `is_weekend()` | 按 txn_date 的星期 |
| 某几个月 | `in_months(1,2,3)` | 1–12 |
| 最近 30 天 | `within_days(30)` | 以账期末日为锚 |
| 指定区间 | `between_dates('2026-01-01','2026-03-31')` | 含端点 |

**前提：原件必须印了时分秒。** 合成样本的 `trade_time` 全是空的，所以 Lab 里跑 18 点过滤会返回「空值 + 缺列说明」——
这是对的，不是 bug：把「没有时间数据」当成「0 笔」是最危险的静默错误。

### 2 行级 · 数值维（能做）

| 想要 | 写法 |
| --- | --- |
| 金额在 1000–5000 | `amount_between(1000, 5000)`（按绝对值） |
| 单笔大于 1 万 | `count(where=amount > 10000)` |
| 余额为负 | `count(where=balance < 0)` |
| 方向为出账 | `count(where=direction == 'out')` |
| 摘要含某词 | 目前没有字符串包含算子（缺口见下） |

### 3 分布维（能做）

| 想要 | 写法 | 结果（疑义样本实测） |
| --- | --- | --- |
| 3σ 之外 | `count(where=zscore() > 3)` | 0 笔（干净样本本就无离群值） |
| 双侧 2σ 之外 | `count(where=abs(zscore()) >= 2)` | 2 笔 |
| 前 20% | `count(where=pct_rank() >= 0.8)` | 2 笔 |
| 90 分位金额 | `quantile(q=0.9)` | 12500.000 |
| 中位数 | `quantile(q=0.5)` | — |

关键设计：`zscore()` / `pct_rank()` 产出的是**一列数**，与 `where=` 天然组合；
不是「一个函数返回筛选结果」。这样 `zscore() > 3`、`pct_rank() >= 0.8`、`abs(zscore()) >= 2` 都自然成立。

### 4 聚合与分组（本来就有）

`sum/mean/median/std/cv/max/min/count`，按对手方 `group_by*`、按自然月 `monthly_values`、
按日终余额 `daily_balances`、序列微积分 `integrate` / `derivative`。

## 还没做的（缺口，按优先级）

问题：字符串匹配缺失——没有 `contains(column='summary', '工资')` 这类算子。解决状态：未做。事后反馈：这条不做，「工资/小贷/网贷/第三方支付」那 14 项语义指标就只能靠内部词库硬编码，业务改不了关键词；下一步应当做成「词库表 + contains 算子」，让关键词可配置、带版本。

问题：分布比较只做了正态口径（均值±kσ），没有稳健口径（中位数±k·MAD）与分位口径的区间筛选。解决状态：未做（分位点 `quantile` 已有，可直接拼）。事后反馈：流水的金额分布长尾很重，3σ 在这种分布上几乎筛不出东西，稳健口径更合适——建议下一步补 `mad()` 与 `iqr()`。

问题：没有「按对手方分组后取某组」的直接算子，只能先 `group_by` 再聚合。解决状态：未做，靠组合可绕。事后反馈：绕得出来就不急，等有真实用例再补。

## 补记（同日）：文本比较与词库已就绪

之前列为缺口的「字符串匹配」已经补上，并顺带把语义分类从代码里搬了出来。

| 新增 | 作用 | 例子 |
| --- | --- | --- |
| `contains(word, column='summary')` | 文本列是否包含某词（忽略大小写与空白） | `count(where=contains(word='工资'))` |
| `matches(pattern, column='summary')` | 正则匹配，写法错直接报错 | `matches(pattern='贷[\\s\\S]{0,4}款')` |
| `in_lexicon(name, column='summary')` | 命中词库 | `count(where=in_lexicon(name='salary'))` |
| 词库表 `features/lexicon.py` | 10 个内置词库（工资/贷款发放/贷款还款/信用卡/网贷/现金/第三方支付/涉赌/虚拟币/关联方），可本地覆盖、带版本 | 见 `library` |

缺列仍然返回**全空**而不是全假——没读到摘要，不等于摘要里没有这些词。

**为什么没有顺势把 14 项语义指标切过来**：对照发现两种约定冲突。
旧口径在「没有命中」时给 `0.0000`，特征引擎给 `none` 并要求写明原因。
前者会让报告看起来「查过了，确实没有」，后者会说「没查到/没数据」。
这不是 bug，是产品口径，得由业务定；定了之后要么给表达式加 guard，要么给映射表加 `zero_when_empty` 标记。
我把它记为「待定约定」而不是悄悄选一个。
