## 算法骨架

```
种子：表头里认出 >=2 个字段（各银行叫法不同也能认）
  ↓
扩散：顺着 y 往下找「形态对得上」的值（日期形/金额形/方向字/流水号形）
      用命中词的包络把带宽长出来，所以右对齐的金额列也能跟上
  ↓
收敛：一列至少命中 3 行才算成立；同一字段长出多条时保留命中最多的
  ↓
三档回落：锚点扩散(0.98) → 几何聚类(0.55~0.85) → 只用表头位置(0.45~0.65)
```

## 一条必须说清的发现

问题：原以为「死模板」的病根是「没有表头就找不到列」，实测不是——封存版的 L2 通用解析 `parse_generic` 本来就是按形态推列的，我把表头整行抹掉，旧路照样读出 6 笔。解决状态：已确认，记在这里，M2 的差异化判据因此要改。事后反馈：如果继续用「有没有表头」当验收，新框架永远是「和旧版一样」，看不出价值；真正的差距在「词本身不准」（拍照歪斜、低分辨率、混版式、OCR 错字），这类样本目前一份都没有。下一步必须先把劣质样本集造出来，否则 M2 剩下的工作无法验收。

## M2 下：切值自己来 + 倾斜校正 + 劣质样本

### 新交付

| 交付物 | 路径 | 作用 |
| --- | --- | --- |
| 自有切行切值 | `capabilities/parse_v2/table_reader.py` | 按列带切行、按形态取值，不再借旧解析器 |
| 倾斜校正 | `capabilities/layout/deskew.py` | 邻近词对斜率中位数估角，坐标层旋转掰正 |
| 劣质样本 | `capabilities/layout/tests/test_degraded.py` | 坐标倾斜 / 拼页 / 真实图像倾斜三类构造 |
| 解析能力升级 | `capabilities/parse_v2/plugin.py` | `parse.layout_v2` v2.0，改用自己的切值器 |

### 证据 1：自有切值器与旧解析器逐笔一致

4 份样本、每笔的 日期 / 方向 / 金额 / 余额 全部相等（含建行的收支分列、微信的无余额列）：

```
icbc   6/6  全部 ok      ccb  6/6  全部 ok
cmb    6/6  全部 ok      wechat 4/4 全部 ok
```

修掉的一个真缺陷：建行收入金额列在某页全空时，原来的实现会把它整列丢掉，
于是收入金额被「就近」吸进支出金额列，方向直接判反（in 变 out）。
现在表头认出来的列即使这一段没有值也保留列带，只是置信度降到 0.4。

### 证据 2：倾斜校正

| 倾斜 | 估计角 | 校正后列数 |
| --- | --- | --- |
| +2° | -2.00° | 6（校正前 2） |
| +5° | -5.00° | 6（校正前 0） |
| -4° | +4.00° | 6（校正前 0） |

校正后逐笔读回：6 笔、金额与日期序列与原件完全一致。

角度估计器换了两次实现，第一次的「投影残差法」被实测证伪：
稀疏页面上每个词自成一簇，残差在 -6°~+6° 之间几乎不变（0.2~0.7），完全没有分辨力。
现在用「邻近词对斜率的中位数」，参数（横向 20 倍字高、纵向 0.8 倍字高）是扫描出来的，
不是拍出来的。

### 证据 3：拼页（两种版式混一份文件）

把工行页与建行页拼成一份 2 页文件：版式检测按页各出一份几何（2/2），
切值读出 9 笔（工行 3 笔 + 建行 6 笔），不是把一种版式套全篇。

### 已知限制（这一档没做到的，逐条）

问题：OCR 通道的倾斜校正只做到「表格还能认回来」，日期列在斜图里不保证认出。解决状态：未修，已降级为断言「至少认出金额列与表格」。事后反馈：OCR 的框是轴对齐包围盒，斜图里字被切并之后斜率会镜像，估角会差半度到两度；要彻底解决得换成带方向的检测框（RapidOCR 给的是四点框，现在取的是外接矩形），这是一次取词层改造，M4 之后再排。

问题：倾斜只用坐标旋转验证，没有做真实扫描件的整页重采样。解决状态：部分验证（150dpi + 3° 的真实图像走过 OCR 通道）。事后反馈：真实拍照件还有透视畸变、光照不均、阴影，这些不是旋转能覆盖的；要上真实件才谈得上「外推能力」。

问题：多页仍按页独立检测，没有槽位先验。解决状态：未做。事后反馈：同版式流水没问题，但「首页有表头、续页没有」的件依赖每页自己长表头；有了 M2 下的表头保留档，短页不会整页丢，但列名可能来自上一页——这一条要等槽位先验补上。
