## 一、最关键的一个：CSS 花括号不平衡

`frontend-admin/src/styles/app.css` 里 `.trust-chip` 规则只写了一半：

```css
/* 错误：缺 background / color 和右花括号 */
.trust-chip { font-size: 12px; padding: 2px 8px; border-radius: 999px;

/* 正确 */
.trust-chip { font-size: 12px; padding: 2px 8px; border-radius: 999px;
  background: #eef4ff; color: #24508f; }
.trust-chip.off { background: #f1f5f9; color: #94a3b8; }
```

后果比想象严重：文件里 570 个 `{` 对 569 个 `}`，**这个未闭合的块把它之后的全部规则都包了进去**，浏览器解析时整段丢弃。

受影响的有：

- `.inline-field`（列清单的自定义字段输入框）
- `.infer-preview` / `.pv-cell`（多页试跑预览）

表现：多页预览的 30 个格子挤成一坨，显示成 `10 219 319 419…`；自定义字段输入框没有边框和间距。

**检查方法**（以后每次改 CSS 都该跑）：

```python
opens = css.count('{'); closes = css.count('}')
assert opens == closes, f'CSS 花括号不平衡: {opens} vs {closes}'
```

浏览器侧确认：`document.styleSheets` 的 `cssRules` 数量比源码规则少，就是有块被整段丢弃。

## 二、列清单组件化后丢了两处

从 Annotate.tsx 抽出 `ColumnFieldList.tsx` 时，列行的 `className` 用的是旧版 `"column-row"`，漏了：

1. `active` 类 → 点画布上的列，右栏对应行不高亮
2. `id={'col-' + tb.id + '-' + i}` → 自动滚动找不到目标

补回后实测：点 `#1` → `active:1`、`selectedOnCanvas:1`，双向对应成立。

## 三、验证方式：CDP 直连 + DOM.setFileInputFiles

headless 浏览器无法点开系统文件选择器，所以前几轮一直没法端到端验证上传流程。这次改用 CDP 协议直接设文件：

```js
const doc = await send('DOM.getDocument', { depth: -1, pierce: true });
const q = await send('DOM.querySelector', { nodeId: doc.root.nodeId, selector: 'input[type=file]' });​
await send('DOM.setFileInputFiles', { files: [PDF_PATH], nodeId: q.nodeId });
```

脚本在 `E:/TMP/cdp_upload.mjs`、`cdp_interact.mjs`、`cdp_step3.mjs`、`cdp_audit.mjs`。
