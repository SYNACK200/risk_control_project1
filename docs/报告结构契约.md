# 报告结构契约

算法层输出的报告（algorithm/algo/report.py::Report）是前后端、算法与后端之间的稳定约定。
字段顺序与名称由 algorithm/tests/test_report.py::test_report_matches_contract_shape 守住；
**增删字段必须同时改契约与测试**，不允许临时拼装。

## 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| carrier | str | 载体：electronic / image / screenshot |
| verdict | str | 五态结论：未发现异常 / 存在不一致 / 余额可疑 / 来源可疑 / 无法判定 |
| verdict_reason | str | 结论的一句话理由（面向非技术人员） |
| limitations | str[] | 受限说明与不可算项 |
| layers | Layer[] | 四层核验：file / content / ledger / external |
| metrics | Metric[] | 40 项指标值 |
| metric_set_version | int | 指标口径版本 |
| threshold_version | int | 阈值版本 |
| conclusions | Conclusion[] | 风险结论（编码 + 文案） |
| scores | Score? | 业务域加权得分（收入/负债/资金/异常/对手方） |
| trust | Trust? | **真实性加权得分**（见下） |
| trend | MonthlyFlow[] | 月度收支 |
| evidence | Evidence[] | 证据（可跳转到页内位置） |
| materials | Material[] | 材料清单 |
| self_check | Check[] | 识别自检（S 系列） |
| version | int | 报告版本 |

## trust：真实性加权得分

五态结论是「规则判定」，只有 5 个取值，无法反映「核验做了多少、结论有多硬」。
trust 是它的量化补充。

```json
{
  "score": 82.4,          // 0-100
  "level": "high",        // high / medium / low / unknown
  "label": "较高",
  "carrier": "image",
  "note": "载体为 image，载体层权重已下调",
  "layers": [
    { "layer": "content", "label": "内容层", "status": "pass", "score": 100, "weight": 0.53, "note": "" },
    { "layer": "file",    "label": "载体层", "status": "limited", "score": 70,  "weight": 0.12, "note": "影像件，不做结构取证" }
  ]
}
```

### 权重设计（为什么载体层与外部层占比要低）

| 层 | 默认权重 | 说明 |
|---|---|---|
| content 内容层 | **0.45** | 识别结果、结构一致性、数据自洽——直接反映「流水本身对不对」 |
| ledger 账务层 | **0.30** | 余额链闭合——流水真伪的硬证据 |
| file 载体层 | **0.15** | PDF 结构取证。借款人上传影像件很常见，载体层本就无法取证，过度加权等于惩罚「用手机拍」 |
| external 外部层 | **0.10** | 跨机构交叉核验。多数场景未接入，权重过高会让总分长期失真 |

### 载体修正

| 载体 | file 系数 | external 系数 |
|---|---|---|
| electronic | 1.0 | 1.0 |
| image | **0.5** | 0.8 |
| screenshot | **0.3** | 0.6 |

降低的权重**按比例回流**到内容层与账务层（它们对影像件仍可测），不是直接丢弃——
否则影像件的真实性永远算不出来。未执行的层**不参与加权**（不把「没查」算成「差」），
只在 note 与各层 note 里标明「未执行，不参与加权」。
