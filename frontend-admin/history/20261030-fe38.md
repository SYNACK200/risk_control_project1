# FE-38 试解析接真实接口

## 意图

银行侧标注页原先的「演示试解析」用的是 `src/mocks/ocr_lines.json` 假数据，只把写死的字段值贴回原页。
FE-38 的验收是：标注后调 `POST /api/v1/templates/infer`，返回真实列与置信度。

## 改动

- `src/pages/Annotate.tsx`：
  - 保留打开样例时的原始 `File` 与口令；仅在点「用当前标注试解析」时用 `FormData` 调 `/templates/infer`，不落库、不保存模板。
  - 标注 → marks：优先取表格列（列中心 x，表头 y 或表格区上沿），没有列字段时退回字段框中心；页码 1-based 转 0-based。
  - 坐标口径：`SamplePage.width/height` 取自 PDF.js `getViewport({scale:1})`，单位已是 PDF pt，直接乘归一化比例即可；不乘 72/96。
  - 结果面板展示每字段的列号、来源（人工标注/统计推断/派生）、置信度、理由、表头别名、列样本与后端告警；低置信（<80%）标黄。
  - 后端 provenance 用 `p.column or 99` 排序会把第 0 列排到最后，前端展示时按列号重排。
  - 拦截条件：无源文件（含内置示例页）、图片件、无标注、无页面尺寸时都给明确提示，不发请求。
  - 任何标注改动会清空上一次试解析结果，避免拿旧结果对新标注。
  - 文案改为「样例在本机读取；点试解析时才发往本机后端」，保存提示改为「试解析结果仅供核对，保存模板请在模板管理里操作」。
- `src/components/Stage.tsx`：删除 `demoLines` 叠加层；渲染改串行队列（pdfjs 禁止同一 canvas 并发 render，StrictMode 双跑 effect 会触发「Cannot use the same canvas」）。
- `src/styles/app.css`：删除 demo 叠加样式，新增结果面板样式。
- `src/lib/demo.ts`：删除 `ocrDemo` / `LOW_CONF` / `DemoLine` / `OcrSample` 类型与 `ocr_lines.json` 引用；保留报告示例数据。
- `src/mocks/ocr_lines.json`：删除（已无引用）。
- `README.md`、`tasks.md`：能力表、限制、目录、示例数据说明同步；FE-38 标完成。

## 验证

- `npm run build`：通过（tsc -b + vite build，244ms）。
- 浏览器联调（Chrome 1440×1000 + 本机后端 8000，Playwright）：17/17。
  - 无样例点试解析：提示先载入 PDF。
  - 载入 `admin-infer.pdf` 后调用 `/templates/infer` 返回 200。
  - 后端返回 4 列，列坐标 50/180/330/450 pt；字段映射 4 个，表头别名 `Date|Summary|Amount|Balance`，无告警。
  - 面板首行 `txn_date 第 1 列 人工标注 置信 99%`，字段/列/来源/置信度齐全。
  - 100% ↔ 135% 缩放切换无画布并发报错。
  - 图片件点试解析：提示只支持 PDF，不发请求。
  - 页面无「渲染失败」提示，无页面脚本错误。

## 没做什么

- 逐格抽取与回贴（dry-run）仍未接入，等后端 `/templates/dry-run`；本轮只做列外推。
- 试解析仅支持 PDF 电子件：后端用 pdfplumber 取字，图片件需先导出 PDF。
- 未用真实客户 PDF 验证：功能测试用的是临时目录生成的英文表头 PDF；中文字体 PDF 的 ToUnicode 差异仍需真实样例复核。
- 未保存模板草稿（不传 `save_draft`）；保存仍走模板管理。

## 风险 / 契约偏差（需 PM/PD 确认）

- `algorithm/ocr/infer.py` 的 provenance 排序 `(p.column is None, p.column or 99)` 把第 0 列当假值排到最后；前端已展示层重排，建议后端改为 `p.column if p.column is not None else 99`。
- 试解析会把样例文件与 PDF 口令发往本机后端（仅内存处理）；与「样例只在本机读取」的旧文案不同，README 与页面已同步。若 PM/PD 要求样例绝不出浏览器，需要改为前端本地推断或明确后端不落盘约束。
- `template-spec.md` 中字段名写 `counterparty`，后端推断用 `counterparty_name`；本轮不涉及该字段的展示冲突，待模板管理联调时统一。
